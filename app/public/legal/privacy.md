# 27. 10X.Social

### Interface, Application Services & Public Networks

**10X.Social**, at [10x.social](https://10x.social), is a web interface operated by Code Hunt Pty Ltd, trading as 10X Meme, for supported Farcaster-connected social features. It is independently branded and operated. Using Farcaster technology and services does not make 10X the operator of those services or imply official-client status, sponsorship or endorsement.

Different parts of the service have different roles:

* **10X.Social and our infrastructure:** operate the interface, process relevant requests, support local sessions/settings and handle enabled diagnostics and analytics.
* **Upstream Farcaster application services:** provide authentication, account, API and other application functionality under their providers' policies. See the [Farcaster privacy notice](https://farcaster.xyz/~/privacy-policy) and [Farcaster terms](https://farcaster.xyz/~/terms-of-use) for those services.
* **Farcaster protocol infrastructure:** distributes supported public social records among independent participants. Snapchain is part of this social-data infrastructure.
* **Public blockchain networks:** record relevant identity/authorization registry events and wallet transactions, with separate public-record and deletion limitations.

These are different data flows. Every item is not copied into all four systems. Public casts, email addresses, authentication tokens, private communications and blockchain transactions have different visibility and handling.

### Login, Sessions & Requested Features

Supported login flows include email magic links and mobile/QR synchronization. We process the information needed for the selected flow, including a supplied email address, account identifiers, device identifiers and authentication/session credentials. Login email requests use the configured upstream API. Authentication/session credentials differ from wallet private keys, seed phrases and protocol signing permissions.

A login can create an ongoing session capable of supported account actions. Ordinary authenticated actions do not necessarily require a fresh mobile approval. Review the permissions and controls offered by the login flow you use, and protect your browser and credentials.

Depending on features enabled and used, processing may include feeds and profiles, casts/posts and replies, reactions, follows, uploaded or fetched media, notifications, and messaging data and related metadata. Private communications are handled according to the relevant feature and provider; we do not promise end-to-end encryption or a particular storage location for messages. We do not treat private communications as public-feed content or acquire promotional permission to them through this Policy.

### Requests Through Our Infrastructure

The reviewed client defaults to a same-origin /~api relay hosted through Cloudflare, forwarding requests to the Farcaster application API. Relayed requests can contain bodies and authorization/device headers, including private account information needed to fulfil a request. Processing through our infrastructure creates privacy responsibilities even where the main account/social backend is upstream.

The API base is configurable, and other connections, including an upstream websocket and requests to external features or media, can take separate routes. Not all traffic passes through our relay, and not all traffic goes directly from your browser to Farcaster. Cache controls do not establish the absence of hosting, security, diagnostic or upstream logs.

### Browser Storage, Analytics & Version Differences

The client uses browser storage, including localforage-backed storage for authentication/onboarding and localStorage for preferences and a stable per-browser device identifier sent to the upstream API. It also supports query-cache persistence. Availability and persistence depend on browser and application settings.

**Revised white-label client.** The revised Social client prepared for coordinated publication disables the inherited **PostHog** integration in white-label mode. It does not initialize that project or send client usage/identity events through that integration, identify users, set account properties, read analytics device/session IDs or request PostHog feature flags. This describes the revised client control; it is not verification that the control has been deployed. Older published, installed or cached versions, and builds with white-label mode disabled, may retain the inherited behavior. Publishing this Policy alone does not update a running client.

**Historical source finding.** An earlier source review on 21 October 2026, before this control was added, found startup PostHog initialization using inherited upstream project settings and the **ph.neynar.com** destination, localStorage persistence, page-leave capture, explicit events, user identification and account-related properties, including some events before login. That review describes the earlier code, not the revised white-label control. An analytics host appearing in a published bundle establishes included configuration, not which events were actually transmitted.
