# Pre-adoption observation replay

Genuine legacy adoption preparation can retain a current asset after B04-backed `collection.observe-asset.v1` events. The current-asset audit checks the original mint and resulting Collect/Vault history; recovery must additionally authenticate each retained normalized observation. A pre-cut event cannot be discarded or treated as a later observation merely because its immutable binding is present.

`createRecoveryLegacyPrecutObservations` is a private, unmounted continuation helper. It requires an actual certificate and anchor, the original-mint semantic proof under the current restore watermark, and the target's private restoring identity. Its caller retains returned contexts using the existing restore checkpoint CAS. Public callers cannot supply contexts or mapped baseline facts. The helper neither writes business rows nor changes readiness.

Start reconstructs the first normalized event's baseline from the retained original operation, ticket/Level, immutable slot, initial Level history and unbound legacy transfer/reveal prefix. Original traits are checked against the original mint digest, and owner/version/reveal/clocks are independently replayed. The retained first `assetBeforeJson` supplies exact JSON bytes only after those checks; its accepted command binding is authenticated when that event is replayed. Legacy events must strictly precede the first normalized observation's event and command times. Interleaving or ambiguous owner ordering explicitly holds.

Each subsequent call replays one accepted normalized event using the existing retained B04/041 verifier. Ordering uses distinct numeric source revisions, bounded by the activation receipt's captured source revision; every pre-cut command must also have been created no later than the fixed preparation cut. The verifier checks original bytes, registered source, evidence and command receipts, before/after effect, Collect observation and Vault event. Current heads and current traits do not replace original evidence.

Completion checks the exact raw asset/Vault digest, current summary and counts against the anchor's accepted preparation commitment, and accounts for all legacy/pre-cut/post-cut event rows. It returns the authenticated adoption-cut baseline, proof chain/counts and activation source boundary. The existing later041 verifier can continue from that baseline. The historical current-source digest is retained as a historical commitment; this adapter does not claim to reproduce its old database selection.

The context cap is 16 KiB, invocation allowance is 64 SQL/object operations including a twelve-operation outer reserve, SQL batch cap is 256 KiB, and combined working cap is 1 MiB including the caller's actual checkpoint copies. Legacy prefix transport is preflight bounded to 98,304 bytes and 1,000 rows; larger retained histories hold rather than exceeding the working bound. The parent owns durable context CAS integration and aggregate completion.

Acceptance uses genuine original mint, legacy prefix, B04/041 reveal and transfer, original audits and preparation, activation, optional later041, and independent fresh targets. Only the target's original-mint prerequisite is explicitly synthesized to isolate this adapter. Full readiness remains false. Interleaved legacy events, progression, claims and conflicts remain unsupported until separate replay adapters exist. All chain/payment provenance remains synthetic local fixture evidence.
