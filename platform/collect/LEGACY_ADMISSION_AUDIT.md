# Historical admission and economic prefix audit

The pure `legacy-admission-audit.mjs` module audits one original admission, including pending admissions, against the canonical 035 source and private historical prerequisites. It returns a compact historical summary and the next economic prefix. It never creates a 045 admission, a 046 fulfillment, a payment record, a chain claim or active inventory authority.

`startLegacyAdmissions(root, ports)` validates the canonical source root and initializes zero counters. `auditLegacyAdmission(input, ports)` validates one exact root/page/cursor entry and returns `audited` or a named `held` result for missing historical facts. Contradictory supplied facts throw a typed error. `finishLegacyAdmissions(root, prefix, ports)` requires consumption of every declared admission page and verifies exact admitted, fulfilled, pending and remaining-quota aggregates. It derives the legacy `inventoryCounts` fields: paid/free/founder count fulfilled entries only; unsold subtracts all admissions; unminted reserve subtracts fulfilled entries.

The prefix contains the source root ID, admission/page cursors, fulfilled/pending and category totals, ten remaining quotas and at most 32 stage counters. Each stage's total cost must equal its original fixed per-admission cost multiplied by admitted count. This keeps pending reservations in allocation, wallet quantity and founder budget accounting. Exact per-wallet count and prior duplicate indices are supplied separately by the future private repository. A structurally valid supplied prefix is not proof that its preceding transcript was verified.

Each step reuses `prepareMintAdmission`, the same reducer used by the legacy `admitMint` path. It preserves the original stage window, total inventory limit, stage allocation, Genesis/free one-per-wallet rule, paid Season published quantity, founder zero price and approved local-cost budget. A wallet may legitimately enter multiple stages. The original request digest preserves the distinct `mint` and `founder` preimages. The original operation's wallet, request key, commitment, creation time, stage, price and local cost must match the selected admission and retained private index facts. No modern quote or normalized receipt is retroactively required. The old operation row does not retain an authenticated founder-operator identity; verifying the founder lane and budget does not certify that missing authentication provenance.

The previously verified stage-publication result must match the original terms digest and full normalized scalar projection. Whitelist/founder membership binds the original list ID and wallet digest. The auditor rehashes its list manifest/closure metadata and one canonical eligibility page containing the original wallet. Free membership additionally requires a separate historical cut-audit fact bound to the original opening time, stage, list and original cut digest. A list alone does not prove complete historical ownership. Public membership remains unrestricted. Missing original publication, membership or free-cut facts hold; none is inferred from current holdings.

Historical control facts are distinct from caller authorization. They bind root, operation, original admission time, scope, retained source digest, original pause revision and original cost-pressure result. The pure step checks the exact legacy decision shape: collection mint remains allowed at a budget warning; pause or limit rejects. A later pause is irrelevant to an already captured original decision. This module does not prove that an arbitrary supplied historical decision's source is complete. A future private audit must independently verify and select those retained source facts; absence of such verification must remain held. The digest is a binding, not an approval credential.

For the first admission of a later Genesis tranche, the original opening decision and previous-tranche supply fact are required. The original decision must allow the admission time; prior unsold inventory requires the original explicit override rationale. The facts are tied to the first published stage's ballot. Current ballot decisions or current supply cannot substitute for the original admission boundary.

Pending rows must have no Level, proof, ticket, settlement time, evidence digest or receipt. Settled rows must precede every pending row, consume the exact quota ticket and carry the independent B11-27 original mint audit bound to the same root, page, ordinal, operation, wallet, Level and evidence digest. The original receipt is also checked against that audited asset and settlement time. The next quota prefix must match B11-27. Missing original mint evidence holds, preserving original history rather than inventing a fulfilled receipt.

Prior index facts must be produced under the same frozen historical source and verified prefix. They include per-stage/wallet count plus duplicate operation, commitment, owner/request-key and proof counts. The owner/request-key scope includes the original global operation namespace, not merely one inventory's admissions. This pure module cannot prove an externally supplied zero count. The future repository must provide bounded indexed reads and source fencing. The Node fixture computes these facts from actual legacy rows; the Worker fixture loads exact original operation rows from D1 while its other prerequisites remain explicit synthetic fixture inputs. The one-D1-read metric covers that fixture's named operation read, not a production historical index implementation.

Each step accepts a root up to 128 KiB, one admission page up to 64 KiB, one eligibility page up to 8 KiB (at most 100 canonical wallets), and 32 KiB of captured context. It copies inputs before the first await and limits conservative working-payload accounting to 1 MiB. These format/resource boundaries are explicit audit limits, not altered historical economics. Whole-component source verification, original control/cut retention and guarded prefix reachability are prerequisites. No stricter normalized economic rule was introduced: the original reducer is reused unchanged. Unsupported or absent original evidence stays held; no historical row is silently normalized or upgraded.

Acceptance uses actual legacy store reservations and fulfillment for settled/pending economics, all 1,000 slots across ten source pages, Genesis wallet limits and later stages, founder pending-spend budgets, free and public membership, budget warnings and later pauses, missing prerequisites, corruption, duplicate keys and caller mutation. A focused actual workerd/D1 test compares the full Node results, checks held/error parity and verifies zero fabricated 045/046 rows. A separate later-tranche boundary case supplies explicitly synthetic private prior-decision facts; it does not claim a new governance provenance verifier.
