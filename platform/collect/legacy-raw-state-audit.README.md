# Private exact legacy byte audit

`createLegacyRawStateAudit` fingerprints the original `collect_inventories.state` bytes without parsing, canonicalizing or replacing them. Each continuation executes three bounded SQL statements: header/pin, one64KiB BLOB byte slice encoded as hex, then the same header/pin. Both headers must agree. The pin retains original header fields, recovery generation/mode/status and whole-business mutation watermark. Any intervening business mutation, including state changes without a header revision increment, invalidates the continuation. Restoring sources hold. Header strings are bounded in SQL before transport.

A fresh injected B11-24 pinned hash adapter resumes from the captured state on every invocation. Maximum input32MiB takes512steps rather than512SQL reads in one invocation. No complete state is returned to JavaScript. Hex decoding preserves split UTF8 code points and NUL bytes exactly. Metrics conservatively count serialized result copies, hex copies, byte/hash copies and checkpoints; they are serializedworking estimates, not VM heap measurements. Each step remains below64operations,256KiB SQL/result limits and1MiB measuredworking. An interrupted read has no writes and can retry the exact prefix.

The checkpoint is private resumable data, not an authorization token. Valid-looking hash words do not prove a reachable prefix. A future guarded repository must own checkpoint creation, source pinning, cursor progression and durable compare-and-swap. This read-only seam writes no receipt, creates no authority and exposes no route. Schema identity and final source CAS belong to that repository. A verified result means exact raw-byte SHA256 only: no valid JSON, canonical projection relation, original stage approval, mint economics or adoption is inferred.

Acceptance uses installed schema, genuine local D1 and fresh pinned hash adapters for each Node/workerd invocation. A900014-byte Unicode/control-character JSON fixture takes14matched steps; a synthetic32MiB NUL-byte Node row takes512steps. The latter deliberately is not valid inventory JSON and does not claim D1 can store32MiB in a single value. The separately recorded pinned D1 single-value limit remains an adoption constraint. Mutation, missing/oversized/restoring data, read loss, malformed chunk and cursor tests fail closed. No financial execution or remote resource use.
