# Private fixed-cut Season eligibility

The normalized free-cut pipeline retains a synthetic operator ownership transcript at the free stage's original published opening time. It compares every locally known Genesis holding in each page interval with retained ownership and reveal evidence, then attaches one immutable eligibility-list binding. This checkpoint does not enable free mint admission or mount a public route. Financial execution remains disabled.

The input is canonical UTF-8, independently hashed and stored as immutable JSON records. Each holding page contains at most100 sorted unique IDs, and a root references at most100 pages/10,000 holdings. The paged root hash is explicitly a `paged-fixed-cut-v1` commitment. It is not the legacy flat snapshot hash. Source bytes or a supplied completeness boolean do not establish chain provenance; external additions retain their synthetic fixture label.

Stage all cut pages/root and the existing immutable eligibility list first. The list must be sealed and fully indexed. `beginCut` verifies that closure and captures the current source revision in an immutable attempt. `validatePage` checks the interval from the preceding page's last ID through this page's last ID; the first interval includes the beginning and the final interval includes the entire tail. An empty cut checks the whole ID space. The repository reads at most101 known Genesis rows and refuses an overfull interval. It selects actual owner observations at or before the cut and projects only bounded owner/identity/time fields from their JSON. Missing, malformed, contradictory, omitted or future-bound local identities hold the command.

`sealCut` loads compact page summaries rather than the entire holdings graph. It derives sorted unique eligible wallets using the existing Level1/revealed-at-cut policy, then requires an exact count/digest/indexed-list match. The final SQL guard independently verifies known-Genesis coverage and actual eligible set membership. Source changes between validations invalidate the attempt; stage another attempt under a new request key after the inputs are ready. The old attempt and receipts remain available for audit.

All commands use `collection-evidence` operator authorization and the existing `collection-mint` pause/budget controls. Metadata writes advance the recovery watermark while preserving the attempt's source revision; final binding advances source once. Accepted retries return the exact original receipt before new authority/clock checks. Changed-body retries conflict. Concurrent claimants resolve the accepted receipt without creating duplicate approval. The final transaction independently guards source/control revisions and a30-second trusted preparation window.

The four tables introduced by047 are cut records, attempts, page validations and final free-cut bindings. Published stage terms and legacy `collect_snapshots` remain unchanged. Recovery includes all four tables, their original command receipts and the existing eligibility records/index. Private recovery preserves accepted replay after operator revocation and source object loss; held/public targets reject new cut writes.

Acceptance includes the complete10,000-holding Node command transcript with100 real locally tracked Genesis observations and9,900 explicitly external synthetic additions, plus actual D1 validation of the maximum known-Genesis page and final10,000-wallet seal over100 retained validations. The capacity fixture copies genuine accepted local records for99 checks and deliberately leaves the first check and final binding absent so workerd must execute them. This is documented local fixture setup, not a new recovery mechanism.
