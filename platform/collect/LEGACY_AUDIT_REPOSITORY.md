# Private durable legacy fingerprint audit

Migration050 adds `app_collection_legacy_audits`, a temporary control table for exact raw-state and035 canonical-projection fingerprint continuations. `createLegacyAuditRepository` exposes private `start(operator,{auditId,inventoryId,rootId})` and `step(operator,{auditId,expectedRevision})`. There is no public route or capability. Callers cannot provide checkpoints, hash words, raw digests or proposed output.

Start requires current collection-import scope and a sealed035source root whose inventory/revision matches the legacy header. It captures the installed schema and exact business-watermark trigger inventory using the existing private recovery metadata verifier. The source generation, whole-business watermark and descriptor are immutable. Original root and declaration are inputs to audit, not trusted source correctness.

Each step loads its private bounded prefix, computes one raw-byte or canonical step, and commits one control-row compare-and-swap. SQL independently checks the current operator scope, frozen source generation/watermark/header, exact installed schema, previous phase/revision/checkpoint/digests and fresh nonce. It stores no full legacy state. Exact schema comparison runs inside SQLite against the stored descriptor, avoiding a large JavaScript descriptor copy per continuation. Concurrent same-revision steps have one winner; lost acknowledgements recover its durable prefix. Omitted writes, reused nonces, forged loaded checkpoints, scope/source/schema changes and missing original records cannot publish progress.

Raw completion advances to a fresh canonical prefix. Ready requires the computed canonical digest to equal the immutable root declaration and an explicit nonnull SQL field. SQLite CHECK(NULL) semantics must not weaken that mandatory effect. The result remains `fingerprints-ready`, with sourceRelation/economics/adoption/executable false. These fingerprints do not prove raw JSON relates to the035projection, historically valid stage inputs, admission budgets, original mint evidence or current chain ownership. Later adoption must consume separately verified prerequisites and use ordinary guarded collection command receipts; this preparatory control workflow creates none.

The table is excluded from business recovery and the business watermark: updating a read-audit prefix cannot invalidate its own source pin. No accepted operation, financial receipt or active authority is omitted. A fresh recovery target has no audit prefixes; generation changes make old fingerprints unusable. Any real business mutation or scope change invalidates the frozen source. Held/stale audits require a new identity and fresh source capture, never silently refresh their pin.
