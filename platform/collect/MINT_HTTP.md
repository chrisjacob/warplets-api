# Local member mint reservations

Node and local Worker expose `POST /api/v1/collect/inventories/{id}/stages/{stage}/reservations` through the shared `collection-fixture-requests` capability. Requests require a message-authenticated wallet session, same origin, a bounded JSON body containing only `expectedTermsDigest`, and an `Idempotency-Key`. The digest is the immutable published stage terms reviewed by the member. All financial execution and transaction signing/broadcast capabilities remain false.

Normalized inventories use the guarded045/049 admission service. Fixed free-stage membership comes only from a sealed047 opening cut. Founder allocations remain operator-only. The server resolves accepted exact retries before current stage time, operating pause or availability checks; a changed body conflicts. New ineligible wallets return403, changed/unavailable reviewed stage terms return409, and missing evidence or operating holds return503.

The response discloses a local operation identity, wallet, stage, terms digest, published price/cost and evidence status. It contains no draw commitment, ordinal, entropy round, hidden traits or Level. Owned operation reads retain the normalized terms link and may show later fulfillment; the accepted reservation replay remains its original result. Another wallet cannot read that operation.

The React review retains the exact body/key and public reviewed terms before sending. A dropped or mismatched response preserves the request; retry after reload uses the same body/key even if the stage closed or paused. Wallet changes isolate retained requests and private queries. Cost text separates disclosed local creation cost from unknown network and total cost. No SOL is paid by this preview.

Node preserves existing raw empty-body legacy fixture calls. Newly generated clients always send the reviewed digest; the legacy transaction verifies it against the immutable stage before returning or creating a reservation, including accepted retries. This compatibility adapter does not create normalized authority,045 receipts or new historical provenance. The Worker does not activate legacy admission: its inventory read marks that path unavailable while preserving supported reads. Large legacy source adoption remains separate work.

Acceptance includes real Ed25519 sessions in both mounted Node and workerd routes, concurrent identical requests, changed-body conflict, pause retry, owner-scoped receipt, logout/expiry, fixed-cut admission and independent SQL guards. Browser evidence covers four widths, dropped committed response, reload, account isolation, close/pause retry, expiry before confirmation and mismatched response retention. Evidence is recorded in `platform/validation/runs/2026-11-06-overnight/B11-23-member-mint.json` after the checkpoint completes.
