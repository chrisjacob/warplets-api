# Retained historical collection controls

`createLegacyControlAudit({driver, crypto}).read(request)` is a private, read-only source adapter for the B11-31 historical admission audit. It replaces the synthetic fixture control prerequisite with a fact derived from retained database history. Its request names one sealed 035 root, original mint operation and admission time, plus the private frozen inventory revision, recovery generation and whole-business watermark.

A successful result contains the exact B11-31 `controlFact` shape, the frozen source pin, the derived pressure, bounded-read metrics and `provenance: retained-history-as-of`. This means the selected retained rows produce that decision at the original operation timestamp. It does not prove what the database contained when the admission was originally ingested. Late-entered history can change the reconstructed historical decision. Missing ingestion timestamps, original authentication, payment evidence or chain provenance are not manufactured. The reader does not authorize an operator, activate an inventory or write any business or audit row. Its source pin must come from the future guarded private audit workflow; an arbitrary caller-supplied pin is not permission.

The initial atomic batch contains four named reads: source/header/root/operation binding; the latest as-of collection-mint scope rows; the existing operations usage selection; and the existing optional-spend selection. Export-only `historicalUsageSql` and `historicalSpendSql` aliases expose the unchanged statements from `storage/atomic-operations.mjs`. No predicate or existing operations behavior changes. Two scope rows are read only to detect an ambiguous latest timestamp; the latest row determines the decision.

The shared `committedCollectionSourceSealSql` guard requires the exact committed root-staging and source-seal receipt lineage, including input/ref/body/size/format bindings. Separate uncommitted root and uncommitted seal fixtures are rejected without disabling immutable triggers. This lineage proves retained intake closure only. The reader verifies the sealed root's inventory and source revision against the live frozen collection header. It checks the original header digest, header fields, canonical operation wallet, mint kind and original creation time. The request time must equal `collect_operations.created_ms`; callers cannot move the decision to a convenient time. Recovery mode/status must be readable, no restore write nonce may be active, and generation/watermark must match the frozen pin. After hashing the selected retained transcript it rereads the entire binding in a second atomic batch and compares it exactly. Any relevant business, generation, header or root change holds the result. Returned database rows and request values are captured before injected awaits.

The latest scope receipt and selected usage receipt hashes are verified from their exact original preimages. Row identities, decimal amounts, names, periods and timestamps are validated before `pressureFromRows` and `decisionFromRows` run. Monthly run rates carry forward until replaced. Daily quotas apply only to the original UTC day. Optional spend settled after the original admission still contributes its original reserved ceiling at that time. The pre-021 legacy `settled_ms = NULL` fallback is preserved rather than silently assigning a new settlement clock. Collection mint remains allowed at budget warning; a pause or limit produces a verified denied historical decision, which B11-31 rejects as inconsistent with admission. Missing root/operation/source metadata, malformed history, ambiguous latest rows or overflow return explicit held reasons.

The usage and spend queries retain their 101-row overflow sentinel; at most 100 of each are accepted. SQL wraps the exact selections with per-column byte checks and an aggregate serialized JSON-byte budget before returning values to JavaScript. The aggregate is measured using SQLite `json_object` byte length, so escaped control characters cannot evade it. Oversized columns or aggregate payloads return bounded null projections and a failure marker. Each selected table is limited to 64 KiB of serialized source rows; the scope and header selections each use an 8 KiB budget. Total returned SQL data is capped at 256 KiB. Whole-step conservative working-payload accounting includes row snapshots, canonical transcript/hash buffers, request context and the final fence reread, and is capped at 1 MiB. The metric is not JavaScript heap profiling or a claim that arbitrary unindexed source history has constant execution cost.

Acceptance uses actual legacy control functions, actual immutable 035 staging/seals and actual legacy mint rows. It covers empty retained history, historical pause/resume, prior-month carry, UTC daily limits, warning/limit behavior, future settlement and legacy null-clock fallback, missing/wrong bindings, source/generation mutation during hashing, caller/driver-row mutation, 101-row overflow, malformed and oversized projected values, aggregate Unicode/escaped-string bounds and the maximum 100 usage plus 100 spend rows. The existing control and atomic-operations suites run unchanged. An actual Worker/D1 test compares the complete result and source digest with Node, proves read-only source stability and exercises stale-source/oversized projection failures.

The D1 fixture copies exact synthetic original rows and source receipts. Its loader naturally produces different watermark counts, so both fixtures advance their watermarks by legal single-step increments to the same frozen value before comparison. No guard is disabled and no watermark is lowered. The fixture's source-change fault is an explicit local test mutation. No public route exists.

B11-44 adds `capture(request)` alongside the unchanged `read(request)` result. Capture retains the exact canonical `legacy-control-history-as-of-v1` transcript whose byte digest already binds the control fact. The exported private `verifyLegacyControlSelection(document,{crypto})` validates the original selected rows, receipt preimages, ordering and reducer independently of current tables. This supports archiving the selection before later history arrivals. Neither the document nor its hash proves original ingestion-time completeness, operator authentication or adoption authority.
