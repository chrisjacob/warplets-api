# Historical mint preimage audit

`auditLegacyMint` verifies one settled historical mint and returns a private audit summary plus the next ordered quota prefix. It does not activate an inventory, adopt an asset, create a receipt, or authorize minting. All output is `source: local-fixture`, `executable: false`. Beacon signature verification establishes the pinned offline randomness transcript; it does not establish payment or chain mint provenance.

The caller supplies the immutable 035 source root and its selected admission page, the original operation and receipt, original proof inputs, original Collect/Vault binding facts, and the original Season Level history event. The auditor hashes and validates the two source records, binds the admission to its original operation, reproduces the exact historical evidence digest and receipt, and derives initial Level, slot and Season expiry from the preceding quota prefix. Original trait strings retain whitespace and the original `{model, backdrop, symbol}` JSON order. Later ownership transfers, reveal, upgrades and visual rerolls do not replace those facts. Missing original manual proof inputs return `original-mint-preimage-missing`; contradictory supplied inputs reject.

The prefix is a prerequisite from earlier private verified steps, not a caller approval flag. This pure function does not prove that arbitrary counters or page cursors are reachable, that an entire 035 graph has been economically validated, or that supplied operation/policy facts were selected from authoritative historical storage. A future guarded repository must bind root, source identity, original row mapping, prefix, cursor and immutable retained-object identities. It must select whether the original operation was configured; callers must not downgrade configured operations to manual proofs. Current mutable policy rows are not an implicit substitute for retained original policy inputs. No 045 admission or 046 fulfillment receipt is invented.

Configured proofs retain the original policy inputs, request and result independently. The policy is reconstructed with the unchanged `10x-lab-draw-1` preimage: inventory, pinned chain, lead time, publication time, the 1,000 ordered reserved asset IDs, Level quotas and weighted traits. Each trait field has one to four canonical array objects, at most 64 choices per object, at most 256 choices total. Exact raw UTF-8 objects are content-addressed and individually limited to 65,536 bytes. Duplicate names across pages reject. Array order and string whitespace remain unchanged. The first pass hashes the full original policy through an injected private native digest writer. A second pass rereads each trait object by the same byte identity to select the exact original choice. Every reread verifies its byte digest. The original request, signed round, pinned BLS verification, proof ID, ticket, reserved asset and retained result fixture must all agree. Missing retained inputs hold with a named reason; false or malformed beacon signatures reject with `legacy-mint-beacon-verification`.

The storage port must check an object's declared size before hydrating its body. The Worker fixture demonstrates that with local R2 metadata, then the pure module checks the actual byte length and digest. The digest writer is created and completed within one invocation; interruption restarts the audit. This module has no resumable stream state or SQL continuation authority.

Bounds are one source root (128 KiB), one admission page (64 KiB), and 48 KiB of original context. The root/page graphs are released after extracting the selected compact facts. Configured policy verification uses at most 25 object reads. The recorded working-payload calculation includes retained context, source decoding/canonical copies, part-byte copies, decoded/canonical trait pages, duplicate-name tracking, reserved IDs and stream overhead; it rejects above 1 MiB. This is conservative serialized working-payload accounting, not a measurement of the JavaScript engine's heap or garbage collector. The reader and digest implementation are trusted bounded ports.

The maximum escaped-name fixture has 600,611 bytes of legacy trait JSON, 50,049 bytes in its largest part, and 1,248,116 total bytes read across 25 reads. Final Node and actual workerd/R2 acceptance measure about 773 KiB of conservative working payload. The real Worker test uses retained round 30,000,000 and the pinned BLS verifier; dependency-free Node reference tests explicitly inject a synthetic verifier for arithmetic cases. The fixture constructs actual legacy operations through the legacy reference store. Tests cover all ten initial Levels for Genesis and Season, ordered quota progression, hidden/revealed assets, later owner/Level/trait changes, original receipt and history corruption, cross-page duplicate traits, caller mutation across awaits, changed second-pass bytes, absent objects, oversized objects and malformed signatures.

The legal legacy policy above 512 KiB remains a compatibility gap for the active normalized mint reader. This audit's partitioned historical verification does not enlarge that active guard, install a schema, add a public route, or close adoption readiness. Named private fact retrieval, original-proof retention, historical source mapping, ordered full-component reconciliation and guarded activation remain separate work.
