# Imported collection authority reader

`createLegacyAdoptionAuthorityReader({driver,crypto}).read({inventoryId,stageId,wallet})` is a private bounded read adapter. It returns `absent`, `pending` with a named integrity reason, or accepted certificate/current authority facts. It does not activate an import, authorize a mint, verify payment, or publish a route.

The reader verifies canonical economic/preparation results, retained parent preimage and final quiescence body against their digests; their source, counts, fixed preparation time and flags must match the certificate. The certificate commitment includes the original collection origin digest and every certificate scalar except the allocated activation receipt ID. That ID is independently joined to the authority and exact committed parent receipt. Parent and child request/output hashes, principal, business identity, request identity, time and result reference must agree. Current operator permissions are not re-required for accepted immutable effects.

The named035 root is independently byte-verified in a bounded scope and released before subsequent aggregation. Its identity, revision, canonical digest, kind/tranche, counts and remaining quotas must match the certificate/current header. Only32 small hashes of the verified stage terms survive that scope; each imported stage and its fixed list identity is checked against them. Economic stage counts and exact spend are also bound to those frozen terms. The original header tuple `[id,kind,tranche,season_start]` is hashed independently and bound to the retained certificate origin digest; the UTC Season month must agree. This prevents a jointly altered start/origin from borrowing the accepted certificate.

Counts use historical mint anchors UNION ALL modern045 admissions. Global operation, commitment, ordinal and wallet/request-key uniqueness plus complete ordinal prefix and exact actual operation coverage are checked. Historical settled fields and modern committed045/046 linkage must agree with original Collect rows. Every counted row must match the immutable stage's exact decimal price/cost and terms digest. Founder spending is computed with JavaScript BigInt as stage count times the verified identical stage cost; SQLite never sums monetary amounts. Current remaining quotas use each modern046 immutable initial draw level, never the asset's later presentation level.

The whole read is fenced by source revision, business watermark, runtime generation/mode and authority revision. Historical source generation/watermark remain retained history: they are not required to equal a valid later active database. Mutation callers must resolve accepted replay first, call this reader before loading a large fair-policy context, compare its returned fence with their own captured snapshot, and recheck that identity/revision in the actual guarded claim. The reader is not an economic restoration verifier and does not prove that current asset mutations follow supported history.

Limits: at most64 SQL statements,256KiB per SQL batch and1MiB estimated serialized working memory. At most32 imported stages are read as two small receipt pairs per query. The root is bounded to128KiB; no full legacy state,1000-operation array or10000-wallet list is hydrated.

## Current acceptance scope

Node openDatabase and actual workerd/D1 localRuntime apply the installed054 migration. There is no copied schema or draft loader. Test fixtures retain genuine reference-store legacy stages/mints and035 source intake, but load **synthetic accepted import receipts** under a fixture-only private restore nonce. Their synthetic recovery checkpoint explicitly has `verifiedRecovery:false`. These tests prove the read contract and corruption handling, not actual activation or successful restore readiness. One modern admission is likewise synthetic for counter composition; its following B04 evidence ingestion and046 fulfillment use the real guarded services. The genuine activation-to-reader and imported-source recovery sequence remains coordinator-owned integration work.
