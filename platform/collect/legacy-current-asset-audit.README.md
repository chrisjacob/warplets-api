# Private legacy current-asset audit

`createLegacyCurrentAssetAudit({driver, crypto})` exposes `read` for one named035 admission and `closure` for inventory quiescence. Both are read-only private audit components. There is no route, migration, import, publication, custody, payment verification or activation authority. The declaration file specifies the complete result shapes.

The caller supplies the frozen source root, inventory revision, recovery generation, whole-business watermark and evaluation time. Per-asset reads also supply the original admission ordinal/page/entry cursor.38 verifies the named source record against the actual legacy database row and loads retained original mint bindings.43 then checks current Collect/Vault identity, slot, private NFT shape and original evidence, reconstructs supported later ownership history, and rechecks the source pin after the last digest await. A durable caller must additionally fence the exact schema and select a genuine ready051 relation and052 economic audit; caller-provided ordinal prefixes are never authority here.

## Supported history

Original Genesis and Season mints are supported across all ten Levels. Exact current traits, including valid historical whitespace, are hashed with the original mint ticket, operation, commitment, asset, proof and settlement time. The digest must equal the retained original evidence digest. No original trait value is inferred from a name, Level or mutable display projection. Original economic/randomness verification remains27/39/52's responsibility, including the configured BLS verification when that profile applies.

Actual legacy or B04-bound transfer/reveal observations are matched to their exact retained digests and Vault events. Current owner and version follow the complete transfer chain; current reveal/observation clocks follow the recorded observations. Genesis slot and Season original expiry remain exact. Equal-time transfers use the unique owner chain, independent of database rowid and event-ID order. Ambiguous equal-time cycles are held.

Completed legacy or normalized progression currently returns `current-asset-progression-history-unsupported`. Vault claim histories return `current-asset-vault-history-unsupported`. Neither is accepted merely because current JSON looks plausible. A future profile must replay retained original draw/effects and full Level history. Pending locks, unresolved progression, missing paired observations, permanent external-transfer conflicts and unsupported Level history also hold. A normal transfer of a historical asset with whitespace is valid here, while the newer quote validator can independently hold such traits as `invalid-asset-traits`; this audit does not make that asset progression-eligible.

## Coverage and resource bounds

The inventory closure compares frozen admission/fulfilled/mint/asset/Vault counts, distinct minted assets, missing/extra bindings, pending operations, locks, malformed operations and permanent transfer conflicts. It is a count/identity closure only: **it never asserts that all per-asset proofs were executed**. A future durable preparation must retain one successful current-asset proof for every named admission ordinal under the same source pin and enforce that coverage separately.

Each successful asset call uses29 SQL statements and closure uses8. The local limits remain64 statements,256KiB serialized SQL batch and1MiB modeled serialized working state. History stats bound1000 combined Vault/Collect/Level rows and196608 serialized parsed bytes, followed by a stricter complete working-set check. These are explicit supported-history resource bounds, not a claim that arbitrary lifetime histories fit one call. Over-bound histories hold before hydration and require a future continuation profile.

SQL computes both parsed-row and escaped transport bytes before loading the history. Every history SELECT rechecks its exact count and both byte sums in the same statement, preventing a concurrent writer from enlarging transport between stats and hydration. The working model counts encoded and parsed copies, retained original/current facts, proof/hash work and fixed overhead. The final source-pin check still rejects equal-sized or unrelated business mutations. No histories or participants are silently truncated.

Focused Node acceptance covers original outcomes, genuine transfers/reveal, configured original digest compatibility, raw-trait corruption, wrong owner/version/slot/expiry, missing/altered history, equal-time ordering, actual guarded transfer holds, caller mutation, after-hash mutation, and growth before hydration. Actual workerd/D1 acceptance uses150 genuine historical transfers, two original assets, source-race faults, corrupted current traits/clocks and an unquiescent inventory. These are explicitly synthetic local fixtures; they establish no chain or historical operator-authentication claim.
