# Bounded collection reads

`createCollectionReadRepository(driver)` implements four display reads over the same Node and D1 tables: one public asset, the authenticated owner's assets, the owner's operations, and one owner-scoped operation. The shared HTTP handler is `handleCollectionReads(request, {reads, authenticate, consumeQuota, clock})`. It does not serve inventory or stage aggregates and does not imply that Worker mint intake is available.

Each read uses one transactional driver batch containing a source revision before the query, one bounded query, and the revision afterward. Pages fetch at most 26 rows and return 25 with the existing ID cursor. Individual JSON records are bounded at 16 KiB; the final response is bounded at 256 KiB. A corrupt or changed snapshot returns an explicit unavailable result rather than a partial successful page. SQL filters private operations by the authenticated wallet, bounds scalar columns, and withholds concealed or future-reveal asset JSON. It never selects aggregate `inventory.state`, slot coordinates, operation commitments, or raw evidence artifacts. Ownership is checked against the latest bounded ownership observation and current Vault owner. These are local fixture observations, not live chain completeness claims.

The legacy public asset and owner operation DTOs are preserved. Guarded reservations additionally expose their immutable quote ID, binding digest and fairness classification. An unresolved retained external-transfer conflict adds only `reconciliation: {status: 'held', reason: 'external-transfer', observedAt}` to the original owner's operation. `observedAt` is the earliest retained conflicting observation, which can precede reservation time when evidence arrives late. The original status remains `awaiting-evidence`; returning ownership does not clear the hold. No private evidence receipt, previous/new wallet pair or conflict identifier is exposed. The new owner sees the public asset and its pending flag, not the previous owner's operation.

The React receipt view explains the hold without claiming fulfillment, cancellation or refund. Inventory/stage aggregate authority and the remaining B11 fulfillment/recovery work remain separate unfinished work. Local evidence is recorded in `validation/runs/2026-11-06-overnight/B11-11-reads.json`.
