## Bounded phases

The durable phases are inspect, stages, admissions, objects, closure and finish. Empty stage/admission sets skip their phase. Each stage/admission/object step creates one immutable proof and a compare-and-swap cursor update in one atomic batch. Every write repeats the full parent/source/scope fence. A required-child assertion and tail rollback assertion prevent either half of an omitted write from surviving. Lost responses reload the retained nonce/revision, and competing claims create one child. A source, generation, schema or authorization change cannot return prepared success.

Stages retain exact original terms and original private preimage identity, including an existing semantic digest. They prepare *current* `collection.adopt-legacy-stage.v1` command IDs, nonce, request identity and input/request/output digests. They do not fabricate historic publication receipts. Creation time and expected revisions are intentionally absent until a future activation transaction. Unadmitted free stages retain historical snapshot/list metadata separately and prepare pending active eligibility; a hash or retained snapshot row is not new free-cut authority.

An admission anchor verifies all six immutable052 phase hashes and adjacent chains, privately derives its prior prefix, and combines original operation/economic/outcome facts with the actual43 current-asset proof. It keeps original wallet/slot/evidence identity when current ownership has changed. It retains the exact32 control fact and a content-addressed private archive of the selected scope/usage/spend transcript. The additive32 `capture` path preserves the existing `read` result and source digest; `verifyLegacyControlSelection` reproduces the reducer from that retained transcript without substituting later as-of history. This is retained-history semantics, not proof of original database ingestion or operator authentication.

Artifacts use the existing ArtifactStore `putIfAbsent`/`getVerified` contract and private digest key convention. Unknown control-archive writes reconcile exact bytes before their anchor can be recorded. All originals and descriptor parts are independently hashed. Object candidates deduplicate the complete identity, and descriptor expansion retains every referenced part. The processed cursor is a count; selection uses the next unverified key so newly discovered earlier-sorting keys cannot be skipped. Final SQL compares both directions of the expected reference set against candidates, beyond equal counts. No private catalog row, business watermark, command receipt, active collection authority or financial effect is written.
