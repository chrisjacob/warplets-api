# B08 — Publish immutable awards and recover an isolated runtime

**Depends on:** B07. **PRD:** §§7.4–7.5, 13, 14.3; A22, A37, A42, A43. **Owner:** artifact/recovery implementer. Use [CONTRACTS](../CONTRACTS.md), [storage design](../design/storage-earn.md) sections **AE-07/08** and **R2 create-once publication and ambiguous writes**.

## Outcome and inspection

Publish privacy-filtered Earn artifacts through local R2 and recover their read-only projections into a new local database. Inspect `platform/earn/{commitments,archive,archive-cli,recovery-drill}.mjs`, migrations `009`/`012`, `edge/src/worker.ts` manifest route, `edge/test/runtime.test.mjs`, B02 ArtifactStore and B03 jobs. Preserve the existing separate recovery-database rule.

Own proposed `platform/artifacts/{publication,manifest-codec}.mjs`, typed local-R2 adapter orchestration, `platform/recovery/{inventory,export,restore,reconcile}.mjs` and tests. Coordinator assigns `022+` publication/reference migrations and leaves `019` untouched. Reuse the private immutable store interface; this task adds public catalog publication, not another storage abstraction.

## Implementation sequence

1. Serialize a canonical public bundle from committed B07 results, excluding URLs, private moderation notes, sessions and raw source objects. Preserve original semantic commitment formats. Record both `semanticDigest` and SHA-256 `byteDigest`; they are not interchangeable.
2. Persist planned publication identity under a business key, source revision and lease fence. Write bounded bytes create-once at `public/{byteDigest}.json`; verify exact bytes and size, then atomically publish the allowlisted D1 catalog reference.
3. Reconcile interrupted outcomes. Conditional-put failure requires verified existing bytes, not assumed success. Unknown writes retry the same conditional immutable write; a negative read cannot prove an earlier in-flight write failed. Conflicting bytes remain held. Never overwrite or delete published claim artifacts.
4. Retain earlier bundles when a new token allocation expands a board export. Public retrieval verifies byte digest; wallet proofs retain their semantic binding. Expose unavailable status if referenced bytes are missing or invalid.
5. Implement two explicit recovery modes. Public recovery imports independently pinned bundles into a fresh mutation-disabled database. Private recovery includes schema/configuration versions, audit checkpoints, evidence references, command receipts and pending jobs; revoke sessions and fence old leases. Do not combine a partially restored public database with a writable ledger.
6. Reconcile awards plus declared burn, token/day uniqueness, object/catalog completeness, old artifact retention and checkpoint continuity. Chain funded/claimed/burned status stays unproven unless supplied through a separately labeled observation port.

## Acceptance and commands

Crash before/after object put, verification and catalog commit. Test identical/conflicting bytes, duplicate publish, old/new bundle order, missing/corrupt object, private-field exclusion, semantic-versus-byte digest mix-up and stale worker. Restore a fresh local D1/R2 instance and compare original commitments/claim previews, including years-later vesting. Missing private backup must not prevent public read-only recovery or silently enable writes.

## Completion, limits and recovery

Attach independently pinned digest inventory, crash/replay results, restore steps, elapsed local measurements and no-private-data assertions. Keep the existing 2 MiB public manifest bound; measure storage/reads without inventing provider costs. All bindings are local emulations. No remote writes, provisioning, live backup upload, deployment or new probes. Financial flags remain false. A failed restore stays isolated/read-only; failed publication preserves the original award and recoverable object reference rather than rerunning settlement.
