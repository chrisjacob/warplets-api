# B09 — Capability-aware frontend and session lifecycle

**Dependencies:** B00 only. This is an independent parallel lane. **Outcome:** the existing React client renders only supported runtime features, distinguishes unavailable reads from empty results, and handles wallet/session changes without misleading account state. **PRD:** §§3, 11–12; A35–A38, A48–A50. Detail: [product/collections design](../design/product-collections.md), P1.

## Ordered implementation

1. Consume generated `getCapabilities()` once per API origin/version. Validate response and derive availability from advertised method/path pairs. Unknown or failed discovery disables dependent requests/actions with a reason; public policy information can remain accessible.
2. Gate **reads as well as writes**. The current Worker lacks Node collection inventory/asset/operation reads, transaction recovery reads, quotes and local notifications. Do not mount those queries or convert unsupported 404s into empty holdings/history. Canonical collection pages may show supported policy and unavailable detail. Financial flags remain false.
3. Preserve explicit `local-fixture`/`local-rehearsal` labels. Supported local reservation means no payment or NFT mint. Do not infer readiness from a successful health response.
4. Namespace wallet-derived queries by principal, chain and visibility, including personalized stage eligibility. Revoke/invalidate private queries on logout or session expiry. Public SSR continues using fresh cookie-free requests.
5. Use advertised wallet account/disconnect events where available. Cancel stale challenge reviews when accounts change; keep the server-authenticated account distinct from the extension's currently selected account. Never relabel an old session as the new account. Existing message-authentication fixtures remain the test mechanism; do not request real-wallet signatures.
6. Preserve cancellation-safe dialogs, keyboard focus and browser back navigation. On return from an external application, refresh the original session/receipt and check expiry; do not create a second intent. Wallet-specific mobile links wait for B18 evidence.

## Completion, limits and recovery

Record exact commit, capability fixtures, command outputs and screenshots at 360/390/768/1440px. Mark physical-wallet behavior untested. No remote Cloudflare resource/write, spending, real-wallet or transaction signing, broadcast, deployment or new authority probe belongs here.

Rollback is client-only: revert the feature without deleting durable requests. A parser failure leaves a truthful read-only/unavailable screen. Preserve existing public routes, working APIs and private recovery access where the runtime supports them.
