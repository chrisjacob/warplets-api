# B14 — Evidence-bound quotes and read projections

**Dependencies:** B04 and B02. **Priority:** financial preparation. **Mode:** strictly local.

## Outcome and requirements

Serve the existing ATT/OG quote and financial read projections through the portable application/repository contracts. Every result identifies its evidence, applicability and expiry. A recorded comparison harness can compare exact pre-swap state with an existing expected result; missing applicable captured vectors remain missing. Neither fixture success nor a quote creates execution permission.

Preserve LAUNCH-05, EARN-02 and CONTRACTS.md. ATT is token A; OG is token B. Support only the currently validated legacy SPL, OnlyB, timestamp, zero dynamic/compounding configuration. Buy fees reduce OG input; sell fees reduce OG output. Actual activation controls fee decay. Preserve integer rounding, minimum output, original-supply effective FDV and separate network-cost unknowns. Account slot, oracle publication, retrieval and evaluation clocks remain distinct.

## Ordered implementation

1. Map registered market, supply manifest, source policy and B04 receipts into an immutable quote input DTO. Validate identities, approved decoder/program, supported configuration, slots and original oracle publication age before arithmetic.
2. Preserve newest-invalid masking and finalized-slot monotonicity. A newer incomplete observation holds quotes; it cannot select an older favorable state. Conflicting bytes for the same finalized account/slot need an explicit invalid receipt.
3. Call existing BigInt math. Return expected/minimum output, fee side, price impact, spot/effective FDV and source digest. Expire at the earliest evidence expiry, 15-second quote lifetime or next decay second. Mark network/rent unknown; never substitute zero.
4. Port Vault/farm read projections with stable cursors and source status. Distinguish observed accounting from claimable on-chain authority. Keep personalized balances private/no-store and production execution disabled.
5. Define comparison records containing raw pre-swap account digest/bytes, decoder/program identities, current-point input, direction, input amount and observed output/fee deltas. Only compare compatible recorded fixtures. Synthetic SDK cases may verify arithmetic, but cannot satisfy captured-program parity.
6. Expose applicability results: matched, incompatible, missing or failed, with exact reasons. Do not create new protocol transactions or security experiments to fill missing records.
