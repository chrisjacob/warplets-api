# B04 — Build provenance-aware evidence readers and decoders

**Depends on:** B02. **PRD:** §§7.1–7.2, 12, 13, 14.2; A15, A17, A35, A45, A46. **Owner:** evidence adapter implementer. [CONTRACTS](../CONTRACTS.md) defines `EvidenceEnvelopeV1`; [storage design](../design/storage-earn.md) section **AE-04** supplies supporting detail.

## Outcome and inspection

Convert bounded raw observations into explicit verified/pending/incompatible/invalid receipts, preserving origin and coverage. Recorded fixtures are the default. Inspect `platform/pricing/{policy,evidence,fixtures}.mjs`, `platform/earn/{positions,components}.mjs`, `platform/quotes/{accounts,evidence,math,fixtures}.mjs`, `platform/lab/fixtures/`, migrations `006`, `011`, `020`, and B02 private artifact/control ports. Reuse existing raw-account validation rather than introducing a parallel math engine.

Own proposed `platform/evidence/` envelope validators, source registry, ingestion services, typed reader ports and recorded/Solana adapters. Add coordinator-assigned `022+` provenance migrations; leave `019` untouched. Raw objects stay in private immutable storage; D1 holds bounded metadata/references and immutable correction lineage.

## Implementation sequence

1. Adopt the shared envelope exactly: source/mode, chain identity, subject, requested cutoff, context slot, block/oracle time, retrieval/ingestion time, finality, decoder version and byte digest. These are different facts; never rewrite timestamps to manufacture common-slot data.
2. Pin source/program/mint/pool/farm identities and decoder versions. Verify byte digest, owner/layout/discriminator and subject before feeding the existing integer valuation policy. A caller's `finalized:true` is not independent proof.
3. Implement deterministic recorded-response readers. Genuine public captures form decoder vectors only; they do not establish complete historical wallet/ownership coverage. Build complete synthetic transcripts separately and retain their synthetic label throughout.
4. Add an injected, bounded read-only transport adapter if useful. Optional reads may use only public, free, uncredentialed endpoints with hard call/byte/time limits; no charged account, credential retrieval, probing or chain mutation. They are optional evidence enrichment, never required for task acceptance.
5. Preserve pending revisions masking older good observations. Register immutable verified receipts, explicit supersession and coverage gaps. Keep legacy `local-solana`/`solana-local` fixture labels in compatibility decoding; neither becomes real-chain provenance by renaming.
6. Decode enrolled purchase/deposit/withdrawal history in order, including direct activity outside the app. Confirmed events may be provisional. Current account data or `minContextSlot` cannot reconstruct an old cutoff; unavailable historical coverage remains pending.

## Acceptance and commands

Check missing/truncated accounts, wrong identity, stale/future data, decoder drift, partial history pages, missing timestamps, conflicting corrections and a newer pending observation. Duplicate bytes create one stored evidence receipt while every actual provider attempt is metered. Require explicit completeness, not an empty response, before any downstream empty-board conclusion.

Existing checks:

```text
node --test platform/pricing/*.test.mjs platform/earn/components.test.mjs platform/quotes/*.test.mjs
```

Proposed checks:

```text
node --test platform/evidence/*.test.mjs platform/edge/test/evidence.test.mjs
```

## Completion, limits and recovery

Attach decoder/source versions, original byte digests, fixture classification, known coverage, bounded-call counts and test results. Positives must separate synthetic end-to-end data from genuine captured decoder vectors. Do not claim live owner/stake eligibility or a full historical chain transcript.

All writes remain local emulation; no remote Worker/D1/R2 mutation, provisioning, funded operation or new security probe. Financial flags stay false. Retry bounded known transport failures; quarantine identity/schema conflicts. Unknown provider costs block optional calls rather than create an assumed free allowance. A missing source does not block recorded-reader completion; it blocks only the affected live-evidence claim.
