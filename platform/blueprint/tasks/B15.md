# B15 — Unsigned action plans and recoverable intent preparation

**Dependencies:** B12 and B14. **Priority:** financial preparation. **Mode:** strictly local.

## Outcome and requirements

Convert supported user intentions into immutable, typed, unsigned local action plans with exact prerequisites and cost inputs. Port the existing intent/attempt read and recovery semantics through application repositories. There is no signer, broadcaster, payment, custody permission or funded action. An unsupported candidate produces a blocked plan with concrete missing evidence, not invented instructions.

Preserve CONTRACTS.md's stable economic intent versus transaction-attempt distinction. An unknown submitted outcome permits reconciliation only. Replacement applies only to an expired, never-submitted attempt under the same unfulfilled intent. A new blockhash, source revision, program/configuration or funding state invalidates the old packet. No NFT burn action or factory is introduced.

## Existing sources and owned files

Read `platform/transactions/{intents,packets,canonical,http}.mjs`, `platform/transactions/README.md`, `platform/launch/{planner,registry}.mjs`, `platform/quotes/evidence.mjs`, `platform/operations/README.md` and `platform/contracts/capabilities.mjs`. Reuse packet decoding/canonicalization and the existing unknown-outcome state model; do not replace them with browser-supplied instructions.

Proposed ownership: `platform/application/action-plans.ts`, `platform/application/action-recovery.ts`, `platform/transactions/plan-contracts.mjs` and focused unsigned-plan tests. Extend existing intent repositories via B02's contract and scoped authority established in B12. Any new route is explicitly local and nonexecuting.

## Ordered implementation

1. Define a discriminated action vocabulary and versioned schemas. Cover only implemented preparation cases; give other required launch, stake, claim and collection actions a typed `unsupported` result. Separate economic parameters, observed state, desired effects and proposed instruction representation.
2. Derive plans from registered identities and verified application evidence. Bind owner/principal, action/subject, business key, request digest, source revisions, program/configuration identities, quote digest, original activation, expected outputs, maximum fee and expiration. HTTP callers may choose an action and bounded amount; they cannot supply authoritative account lists, recipients or raw instructions.
3. Apply required gates before any wire representation. A first ATT plan must account for the entire split and all unminted Genesis backing, even when the public mint/dashboard is deferred. Unknown custody, farm permissions or asset policy stays explicit. Preserve original Vault clocks and cumulative claims.
4. Reuse exact packet verification where a compatible recorded unsigned message exists. Compare signers, ordered instructions, privileges, lookup evidence and lifetime against independently derived expectations. Do not generate signatures or manufacture simulation success. Missing typed program codecs remain unsupported.
5. Persist intent/attempt preparation atomically using expected revisions and idempotency. Replay returns the original plan; changed payload conflicts. Import only recorded receipt observations through a provenance-aware local adapter. Never promote an application reservation into a paid/minted event.
6. Provide recovery queries listing the exact unresolved attempt, required observation and permitted next local transition. Unknown is not failed; it cannot create a replacement payment. Preserve existing receipt identities during restoration.

node platform/contracts/generate.mjs --check
node --test platform/contracts/capabilities.test.mjs

~~~

Cases include changed recipient/amount, stale quote, mismatched program digest, unknown lookup evidence, duplicate business intent, conflicting idempotency, unsubmitted expiry/replacement and an existing unknown receipt that permits reconciliation only. Compare Node/local D1 transitions. Assert no burn operation, no signing method, no RPC broadcast method and financial capability flags still false. Tests use unsigned data and already-recorded observations only.

## Evidence, limits and recovery

Save representative prepared/blocked plans, state-transition receipts, canonical hashes and test output. Record which action factories are implemented versus specification-only. An interface's existence is not production readiness. Restore the same operation and attempt identities after interruption; hold unverifiable receipts. No remote Cloudflare writes/provisioning, funds, signed transactions or new authority probes. Optional source reads are public, free and uncredentialed; recorded preparation remains the acceptance path.
