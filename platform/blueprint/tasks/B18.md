# B18 — Wallet and marketplace compatibility evidence

**Dependencies:** B09, B15 and B17. **Outcome:** an executable local compatibility harness, evidence-based support matrix and physical-device handoff distinguish tested software behavior from unverified wallet/marketplace execution. **PRD:** §§3.3, 10–12, 17; A07, A33, A38–A40, A48–A50, A57. Detail: [product/collections design](../design/product-collections.md), P6/P8.

## Inspect and own

Inspect `platform/site/src/{wallet-adapters.ts,session.tsx,recovery.tsx,common.tsx}`, `platform/site/tests/{standard-wallet,browser-qa,quote-qa}.mjs`, `platform/transactions/README.md`, B15's unsigned factories/verifier, B17's permission matrix, `platform/lab/CORE-VAULT.md` and `platform/validation/protocol-status.md`.

Own proposed `platform/compatibility/{matrix,harness,fixtures}.mjs`, `platform/compatibility/compatibility.test.mjs`, `platform/compatibility/physical-device-checklist.md` and `platform/validation/wallet-marketplace-matrix.md`; tightly scoped frontend fixes. Existing protocols/providers remain unselected. Do not add a marketplace SDK merely to populate a matrix.

## Ordered implementation

1. Define one row per wallet/browser/OS or venue/asset-standard configuration, with version, feature, evidence type, source commit/digest, date and `passed-local | failed-local | untested | manual-required | incompatible`. Separate discovery/message-auth, unsigned-packet compatibility, physical signing/return, NFT transfer, listing/fill/cancel and royalties. Passing one never implies the others.
2. Extend existing browser fixtures for Wallet Standard registration/removal, account switch, unsupported message feature, altered message, user rejection, dialog cancellation, offline return and expired challenge. Exercise session/private-cache identity and original-receipt recovery. Use disposable existing authentication fixtures; no real user-wallet signatures or transaction signing.
3. Feed B15 unsigned local packets through recorded wallet-capability adapters: supported transaction version, serialized size/account references, expected signer display and exact intent/hash. This is preparation/verification coverage only. No send/broadcast function exists in the harness; an unsupported feature remains unavailable.
4. Define marketplace adapter descriptors and read-only fixture views for asset identity, owner observation, listing state, price age, royalty target/enforcement evidence and remaining Vault value. No verified execution evidence means no native trade CTA or claim of integration. Do not assume a marketplace or wallet supports the candidate Core plugin configuration.
5. Record mandatory future cases: private transfer, actual list/buy/cancel, escrow ownership and post-sale claim authority, royalty realization and metadata refresh visibility. These remain manual/release-gated; no new authority, burn or marketplace probes belong to B18. A missing burn button is not external burn protection.
6. Produce a physical-device checklist covering exact device/browser/wallet versions, connection method, network label, message review, rejection, background/return, account switch, expired request and ambiguous receipt recovery. Provide fields for observed result/evidence. Unperformed cases stay `manual-required`; browser emulation never fills them as passed. Optional host adapters remain deferred.

## Acceptance and commands

Proposed `compatibility.test.mjs`: evidence cannot promote local fixture to physical support; missing/old row stays unverified; incompatible wallet removes only affected action; unsigned packet mismatch fails; no broadcaster or transaction-sign method callable; unknown royalty/price is not zero or guaranteed income. Browser cases verify keyboard focus, long addresses, reduced motion and 360/390/768/1440px layout.

Run `node --test platform/compatibility/compatibility.test.mjs` after creation; `pnpm --dir platform/site test`; `pnpm --dir platform/site build`; installed-browser `node platform/site/tests/browser-qa.mjs`. Use recorded inputs and blocked external requests. Check the matrix against actual collected outputs, not brand documentation alone.

## Completion, limits and recovery

Deliver matrix, fixture hashes, command results, screenshots and the unfilled physical test packet. No remote Cloudflare writes/resources, paid calls, funding, signing, broadcasting, deployment or new authority probes. Physical wallets, custody and marketplace support remain unclaimed until later authorized evidence exists.

Rollback disables the affected adapter/UI capability, retaining evidence and original operation receipts. Never discard an unknown transaction or attempt an automatic replacement to improve a support score.
