# B13 — Complete consent, local notices, usage and retention

**Depends on:** B02 and B12. **PRD:** §§12.2–12.3, 14.1–14.4, 15.4, 19; A35, A37, A42, A44–A46. **Owner:** operations/notifications implementer. Follow [CONTRACTS](../CONTRACTS.md), B12's private operator boundary and [storage design](../design/storage-earn.md) section **AE-09**. Minimum admission/cost controls already exist in B02; do not defer them here.

## Outcome and inspection

Port existing opt-in local-inbox semantics and add privacy-safe usage/readiness reporting across Node and local D1. Inspect `platform/notifications/{notices,http,cli}.mjs`, `operations/{controls,audit,http}.mjs`, `earn/operations.mjs`, migrations `015`, `016`, `018`, `021`, `site/src/notifications.tsx`, current contract schemas and B12 authorization/configuration ports.

Own proposed notification service/repository adapters, `platform/edge/src/notifications.ts`, `platform/observability/{events,metrics,redaction}.mjs`, `operations/readiness.mjs`, bounded maintenance handlers and tests. Coordinate new `022+` migration numbers, keeping `019` untouched. Reuse consent/business identities and existing tables where possible. No external notification channel or provider is selected.

## Implementation sequence

1. Port consent with owner-derived identity, explicit terms/channel/topics, expected revision and scoped idempotency. Disabled remains the default. Revocation cancels pending delivery and removes private inbox records; an old enable-request replay never re-enables consent.
2. Port deterministic enqueue from actual local launch/vote/reward source events. Retain daily wallet limits, TTL, bounded leases/attempts and consent-revision fencing. Never accept arbitrary message text/recipient fields from a public request.
3. Deliver only into the local inbox. Reconcile an expired/unknown lease against its receipt before retry; changed consent or stale worker cannot finish. If B03's runner is available, attach a handler through its contract without duplicating lease authority; otherwise retain the tested notice-specific repository semantics.
4. Expose tested preference/inbox/capability routes in Worker, generate accurate schemas and allow frontend requests only after runtime capabilities advertise them. Preserve private `no-store` and principal-scoped caches.
5. Report B02 usage/settlement counters, staffing headroom, unresolved evidence/jobs, unpublished bundles and held/unknown outcomes. Meter every actual attempt separately from deduplicated effects. Structured logs omit cookies, signatures, raw content URLs, private notes, tokens and evidence bodies.
6. Add bounded retention jobs for transient logs/notice metadata, preserving consent receipts needed for replay and all permanent financial commitments. Readiness reports separate passed/pending/failed evidence with timestamps; it must not turn local green checks into a launch-approved Boolean. Operator detail stays behind B12.

## Acceptance and commands

Race consent update/revoke/delivery; replay old enable; expire a worker; reconcile duplicate source events and unknown results; verify two wallets never share inbox/cache data. Test TTL cleanup boundaries and exclusion of published claim artifacts. Prove monthly pending reservations and actual settlements retain B02 semantics; optional quota stops do not disable existing claim/read recovery or required reconciliation. Insert distinctive sensitive fixture strings and assert logs/public status contain none.

## Completion, limits and recovery

Record consent/replay/fence evidence, retention table policy, privacy assertions, runtime route inventory and measured local resource counts. Unknown real costs stay unknown. No paid telemetry or messaging service, actual message sending, remote Worker/D1/R2 writes, provisioning, production deployment or new probes. Financial flags remain false. Roll back route exposure if parity fails while preserving consent/revocation history and outstanding receipts; never silently resubscribe a user or purge entitlement evidence to meet a storage budget.
