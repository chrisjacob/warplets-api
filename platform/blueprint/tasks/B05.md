# B05 — Construct exact-cutoff completeness manifests

**Depends on:** B03 and B04. **PRD:** §§7.1–7.4, 13; A14, A15, A17, A20, A21, A53, A54. **Owner:** Earn/evidence application implementer. Follow [CONTRACTS](../CONTRACTS.md), [storage design](../design/storage-earn.md) sections **AE-04** and **AE-06**. This task prepares sealed inputs; B07 publishes economic decisions.

## Outcome and inspection

Replace the automated use of a bare `sourceComplete:true` flag with a durable inventory of required facts and coverage. Inspect `platform/earn/workflow.mjs::finalizeBoard`, `components.mjs::deriveComponents`, `positions.mjs::reconcilePosition`, `pricing/evidence.mjs::observationAt`, pure streak/epoch helpers, B03 jobs and B04 evidence receipts. Existing fixture CLI behavior may remain explicitly labeled for regression compatibility.

Own proposed `platform/earn/snapshot.mjs`, `platform/evidence/requirements.mjs`, completeness job handler and tests. Add coordinator-assigned `022+` tables for requirement identities/status, immutable input manifests and dependency versions; preserve `019` gap. Store large private input bytes through B02's ArtifactStore, not public R2 catalog.

## Implementation sequence

1. Define the cutoff using existing UTC epoch precision: final millisecond of the closing day. Keep actual token activation separate. Freeze the admission boundary after close without changing accepted submissions.
2. Enumerate the full required set from the stable epoch version: submitted contributions, final reviews, entry receipts, positive-review closing stake, qualifying-wallet ownership, enrolled purchase positions/history coverage, action/issuer policy revisions, prior-board and late-approval dependencies. Zero-score posts need no irrelevant closing stake read.
3. Select receipts bound to each requested subject/boundary. Distinguish logical cutoff from actual observation time and declared freshness; a fresh current read cannot stand in for an unavailable historical proof. Missing ownership is not zero NFT bonus, and an incomplete purchase journal is not zero credits.
4. Derive a requirements digest and evidence digest from ordered identities, receipt versions and policies. Use B02 dependency revisions to reject a mixed snapshot if a relevant writer changes during assembly. Compute outside SQL; atomically commit only against unchanged revisions.
5. Produce either an immutable complete manifest or explicit pending reasons/dependency IDs. Jobs hold until new evidence or a bounded wake condition. A legitimately empty bootstrap needs positive campaign/history coverage, not merely an empty table/provider result.
6. Bind manifest identity to downstream board plans. Finalized application decisions remain final; late external corrections become incident/reconciliation facts, never silent reranking. Leave old fixture completeness flags out of the automated service path.

## Acceptance and commands

Use a complete synthetic transcript with multiple wallets, a late review, direct withdrawal and ownership/action changes. Then remove each required fact individually and prove only that dependency is pending. Test first-ever valid empty history versus unavailable history, duplicate pages, delayed approval-window streak, exact midnight, correction during assembly and earlier unresolved board. Repeated complete assembly returns the same digest; state changes cannot reuse an old manifest as fresh.

## Completion, limits and recovery

Record the manifest format, dependency enumeration, retained evidence references, digest vectors and pending-to-ready transitions in task evidence. No claim of full real-chain historical coverage follows from synthetic success. Keep registered source thresholds unchanged; the task is completeness plumbing, not a new pricing policy.

All work is local emulation with financial flags false; no remote writes, provisioning, paid calls or new probes. Bound pages, statement parameters and per-tick work through B02/B03. On interrupted assembly, resume from immutable receipts and current revisions; never publish half a manifest or burn for missing data. Founder choices about launch hour and later prices do not block this task.
