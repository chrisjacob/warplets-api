# B07 — Finalize Earn boards and token allocations atomically on D1

**Depends on:** B06 and B03. **PRD:** §§7.2–7.5, 13; A14–A22, A37, A42, A53, A54. **Owner:** Earn settlement implementer. Follow [CONTRACTS](../CONTRACTS.md), [storage design](../design/storage-earn.md) sections **AE-06** and **Guarded D1 commit, step by step**.

## Outcome and inspection

Produce exactly the same immutable rankings, components, awards, declared burns and vesting windows in Node and local D1. Inspect `platform/domain/earn/{board,multiplier,purchases,settlement}.mjs`, `earn/{workflow,components,positions,commitments,archive}.mjs`, migrations `003`, `006`, `009`, B05 completeness manifests and B03 lease/checkpoint interfaces.

Own proposed `platform/earn/settlement-service.mjs`, finalization/allocation job handlers, repository guarded commits and workerd parity tests. Coordinator assigns additive `022+` migration numbers for immutable input/attempt/result references; do not fill `019`. Reuse existing board/award tables and domain functions instead of creating a competing reward engine.

## Implementation sequence

1. Require a complete B05 manifest tied to the exact epoch and current dependencies. Resolve prior-board and late-review requirements; `sourceComplete:true` alone is not accepted by this service.
2. Load bounded inputs consistently and derive existing action, streak, highest eligible NFT and purchased-token-day components. Rank one best eligible contribution per wallet globally; preserve the deterministic tie order and fixed-point arithmetic.
3. Build the board commit plan with ordered decisions, immutable member facts, streaks, winners and input/output digests. Commit through B02 using expected revisions and current job lease. SQL must abort on missing mandatory child records; no partial visible board.
4. Schedule each token/day by actual activation and its designated UTC board. Preserve the existing versioned mapping through day eleven; late evidence does not reset vesting or substitute a different board.
5. Calculate capped proportional allocation with existing domain code. Atomically write unique token/day budget, awards and burn such that awards plus burn equals budget. Duplicate jobs recover the same receipt. Record `burnUnits` as a declared local allocation, not an observed chain burn.
6. Emit durable publication work for B08 without claiming it is already published/funded. Final decisions stay immutable if later external evidence conflicts; record a reconciliation incident instead of changing awards.

Race evidence changes against commit, duplicate finalization/allocation and expired workers. Inject final-child failure and inspect zero partial rows. ## Completion, limits and recovery

Record exact manifests, board/allocation digests, invariant results, statement/byte measurements and source commit. Stay within the current pilot's bounded admitted cohort; high contributor-demand tests must distinguish admission refusals from full settlements. This verifies application decisions, not a funded distributor or real claim balance.

No remote Worker/D1/R2 writes, financial action, provisioning, live schedule or new probes. Financial flags remain false. On incomplete inputs hold the named dependency; on ambiguous commit reconcile its receipt; on revision conflict recompute once within budget. Preserve finalized awards and claim-read access during pause. Never turn provider outage into a valid empty board or unearned burn.
