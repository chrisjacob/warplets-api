# B03 — Add fenced jobs with bounded local invocation

**Depends on:** B02. **PRD:** §§11, 13, 14.3, 15.4; A37, A42, A43, A46. **Owner:** application/jobs implementer. Use [CONTRACTS](../CONTRACTS.md) and [storage design](../design/storage-earn.md) section **AE-05**; this B dependency order is authoritative.

## Outcome and inspection

Introduce one durable, resumable runner for evidence and Earn orchestration. It runs manually against local Node or local workerd bindings; it installs no live cron, Queue, Workflow or remote resource. Inspect `platform/notifications/notices.mjs`, migrations `016` and `018`, `operations/controls.mjs`, `earn/recovery-drill.mjs`, `performance/replay-race.mjs`, and B02 repository/artifact contracts. Reuse fencing concepts, not notification-specific consent/outbox rows.

Own proposed `platform/jobs/{model,runner,handlers,cli}.mjs`, typed job ports/repositories, `platform/edge/src/jobs.ts` and tests. Coordinator assigns new `022+` migration names; `019` remains untouched. Persist jobs with unique business key/payload digest, state, checkpoint, ready time, attempt count/ceiling, lease token/expiry and revision. Keep attempt observations separate from the stable business operation.

## Implementation sequence

1. Define queued, running, held, retry, completed and failed transitions. Enqueue idempotently in the same repository transaction as the source event when possible; otherwise reconcile a durable outbox identity.
2. Acquire a bounded set with atomic lease claims. Every checkpoint, completion and publication verifies current token, revision and lease validity. Restart cannot let an expired worker finish after a replacement.
3. Implement a registry for capture, cutoff, finalization, allocation, publication, reconciliation and retention handlers. Unimplemented handlers return a named hold; they must not fabricate completion. Later cards attach actual services.
4. Invoke through a local CLI and test-callable Worker function. Enforce at most 20 ready jobs per tick and a configurable short deadline. Do not expose a public arbitrary job endpoint or add a production schedule.
5. Reserve applicable optional quota/cost through B02 before any attempt. Meter every provider call, including failed calls and duplicate-byte retries. Use bounded backoff/jitter; held evidence wakes only on new evidence or an explicit bounded schedule.
6. Classify effects: known read transport failures may retry; ambiguous D1 writes reconcile command receipts; object writes reconcile exact bytes and publication state. No transaction broadcaster or private signing capability exists.

## Acceptance and commands

Use fake time and deterministic jitter. Race two runners for one job; replace an expired lease; attempt completion from the stale runner; crash before/after checkpoint and after business commit before response. Assert exactly one business effect, preserved checkpoint and bounded attempts. Test duplicate enqueue with same/different payload, quota exhaustion, a held job resumed by dependency evidence, deadline yield and restart recovery. Unknown outcomes must not silently become failed-and-repeatable.

Existing supporting checks:

```text
node --test platform/notifications/*.test.mjs platform/operations/*.test.mjs
```

Proposed checks/runner:

```text
node --test platform/jobs/*.test.mjs platform/edge/test/jobs.test.mjs
node platform/jobs/cli.mjs --fixture-rehearsal
pnpm --dir platform/edge typecheck
```

Implement the named local-only rehearsal option before using it; no new command is claimed to exist yet.

## Completion, limits and recovery

Evidence records lease races, attempts, operation receipts, restart results and zero external side effects. No-source or not-yet-implemented handler remains held and visible. Preserve the known final result on every replay. Cleanup may remove bounded transient attempt payloads only under retention policy; not immutable business receipts or claim data.

All financial flags remain false. No remote writes, provisioning, new probes or paid services. If a handler repeatedly lacks evidence, checkpoint and continue another ready job; do not busy-loop or purchase a provider. Stop only new optional work at its ceiling while keeping existing claim/read recovery and reconciliation independently usable.
