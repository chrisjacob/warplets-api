# B02 — Implement atomic repositories and minimum operating controls

**Depends on:** B01. **PRD:** §§12.3, 13, 14.3, 15.4; A35, A37, A42, A44, A46. **Owner:** persistence implementer; coordinator owns migration numbers. Follow [CONTRACTS](../CONTRACTS.md) and [storage design](../design/storage-earn.md) sections **AE-02**, **D1 limits and session choices**, and **Guarded D1 commit, step by step**.

## Outcome and inspection

Provide equivalent Node/SQLite and local D1 atomic transitions before admission or jobs depend on them. Include the minimum scope, staffing, cost and private artifact ports now; B13 adds operational surfaces, not these prerequisites. Inspect `storage/database.mjs`, migrations `003`, `006`, `011`, `013`, `015`, `018`, `021`, `earn/operations.mjs`, `operations/{controls,audit}.mjs`, `edge/src/wallet.ts` and `edge/test/runtime.test.mjs` under `platform/`.

Own proposed `platform/storage/{node,d1}/` repositories, shared SQL/row mappings, `platform/artifacts/store.ts` and private Node/R2 adapters. Add coordinator-assigned `022+` migrations; retain the `019` gap. Proposed schema concepts are epoch revisions, command receipts with attempt nonce/state/digests/counts, source/control revisions and fenced atomic counters. Do not create a second accounting ledger.

## Implementation sequence

1. Implement named reads/commands from B01. Use a primary-current D1 session for command preparation; bookmarks supply continuity, not transaction snapshots or authorization.
2. Load bounded input rows plus dependency revisions. Compute outside SQL. In one D1 batch conditionally claim a unique business receipt with a fresh attempt nonce, matching revisions and authority/lease predicates. Gate every child write on that exact attempt.
3. Finalize through a SQL assertion/trigger that aborts on missing mandatory effects. A zero-row update alone does not roll back. Identical committed commands replay; changed payloads conflict. Ambiguous transport results reconcile the stable receipt before retry.
4. Port scope decisions, staffing/capacity enforcement, optional-cost reservations/settlement and provider-attempt metering. Admission predicates must race safely with capacity and scope changes. Preserve pending cost reservations across months and charge actual spend in settlement month. Accepted replays precede new-work stops. Claims/read recovery and reconciliation remain available.
5. Implement immutable private `putIfAbsent`/`getVerified` storage with exact bytes, size and digest. Verify an existing object before treating it as replay. Private evidence never enters `manifest_catalog`; persist its verified reference only after object storage succeeds. Use local filesystem/local R2 only.
6. Measure parameters, statement/batch bytes and returned rows. Respect documented limits and CONTRACTS' conservative application bounds. Stage immutable unpublished plans only if a bounded atomic command genuinely requires it.

## Acceptance and commands

Race the final admission slot, identical/conflicting keys, simultaneous cost reservations, changing scope/staffing during preparation and audit-head updates. Fail the final mandatory write and assert no partial effect. Reopen and recover the same receipt. Check private object collision, interrupted reference insertion and exclusion from public APIs.

## Completion, limits and recovery

Attach exact migration versions, concurrency assertions, Node/D1 result comparison and resource measurements. Reuse the local runtime migration runner; do not maintain a divergent test schema. Both named commands and failure paths must work, not merely compile.

No remote Worker/D1/R2 writes, provisioning, payments, live cron or new security probes. Financial flags stay false. Retry one revision conflict by recomputing; persistent contention becomes explicit pending. Retain unlisted objects for bounded reconciliation, never overwrite conflicting bytes. A storage limitation blocks its dependent task, not permission to add a paid service.
