## Outcome and critical path

Complete one end-to-end vertical slice that can run in Node and a local Workers/D1/R2 runtime: authenticate → admit a bounded contribution using a complete, explicitly synthetic evidence transcript → record final human moderation through the private operator boundary → assemble a complete cutoff snapshot → deterministically finalize and allocate → publish immutable public artifacts → recover a clean instance from independently pinned artifacts. Test genuine captured public-account decoder vectors separately; no existing complete real ownership/purchase/cutoff history is asserted. Retain disabled financial execution throughout. The result should be **ready for a separate hosted nonfinancial-preview review**, not described as a launched reward platform.

The design's dependency path is `AE-01 → AE-02 → AE-03 → AE-04 → AE-05 → AE-06 → AE-07 → AE-08 → AE-09 → AE-10`, subordinate to the authoritative B queue. AE-04 and the contract fixtures for AE-03 can proceed in parallel after interfaces are frozen; one owner must integrate schema changes. AE-02 includes the minimum atomic scope/staffing/cost controls and private artifact storage before admission or jobs; AE-09 only adds observability/readiness over those controls. Stop at a tested milestone if time is insufficient. Do not add a queue product, agent framework, new UI feature, treasury automation or live broadcaster to make the run appear more complete.

All described engineering can proceed without founder input using local fixtures/captured public evidence, the existing package locks and no-charge tooling. The live Sydney launch window, later mint prices, actual staff availability, selected RPC/oracle provider, hosted operator identity and paid services remain configuration/release decisions. They do not block the portable local slice. They must not receive invented defaults that appear founder-approved.

## Concrete findings that shape the implementation

1. `finalizeBoard()` currently runs the entire read/compute/write decision in one synchronous SQLite transaction, including previous-board dependencies, ownership, purchase reconciliation and streak facts. D1 `batch()` is transactional, but application JavaScript does not execute inside that SQL batch. Extract a read snapshot and a guarded commit; do not pretend a generic async transaction callback is equivalent. D1 sessions provide ordering, not a replacement for a multi-statement snapshot. [D1 binding semantics](https://developers.cloudflare.com/d1/worker-api/d1-database/)
2. `sourceComplete:true` in `finalizeBoard()` is an operator attestation, not an independently computed completeness proof. An empty input set is therefore not enough to establish a valid empty board. Completion must enumerate the required evidence before automatic execution is possible.
3. `workflow.mjs` imports `pricing/fixtures.mjs` only to expose `recordStakeRead()` to old tests/demo seeds. Separate that compatibility helper from the hosted application import graph. Likewise `checks.mjs`, `commitments.mjs`, `audit.mjs` and `verifiers.mjs` use Node crypto; port canonical bytes and cryptographic adapters without changing historical hashes.
4. The Earn manifest's `sha256` is a **domain-separated semantic commitment**. Worker `/manifests/{digest}` validates SHA-256 of exact bytes at `public/{digest}.json`. Store both fields explicitly; substituting one for the other breaks retrieval and independent verification.
5. `pricing/policy.mjs` currently allows `network:'local-solana'`; quote capture accepts `network:'solana-local'`. These are fixture labels. Introduce an explicit evidence-source envelope, retain legacy fixture decoding, and never rename imported fixture records into mainnet provenance.
6. `capacityAt()` defaults to 100 when no staffing policy exists. Preserve existing fixture behavior; a separately configured hosted-admission profile must require a staffing record before opening admissions. This is readiness gating, not a new global reward-ranking policy.
7. Purchase events currently say `confirmed:true`, while durable custody/accounting requires a finality policy. Preserve the PRD's confirmed-purchase admission rule, but track provisional versus finalized evidence separately and require a complete, reconciled cutoff before final allocation. Never silently upgrade a boolean to finalized proof.
8. `readWalletClaims()` is a vesting preview that subtracts zero claimed units. The output is not a spendable balance. Port it as a preview until a separately verified distributor claim projection exists; do not add a claim button or execution endpoint in this slice.
9. HTTP metadata currently sets `sourceSlot:null`, and several list snapshots fall back to response time. Evidence-backed routes need stable snapshot/version identifiers; do not imply a consistent chain snapshot just because all HTTP requests succeeded.
10. `archive.recoveryMode()` switches globally when a recovered board exists and import requires a separate recovery database. Maintain that separation. A hosted recovery plan must not mix partially recovered public data with the private writable ledger and quietly resume ingestion.

## Technical conventions for all tasks

- Preserve existing API v1 behavior and local labels while extracting services. Add fields or explicitly version a contract only where required; generate `openapi.json`, `operations.mjs` and `client.d.mts` together. No hand-edited generated files.
- Keep existing `.mjs` domain modules. Define new application ports in TypeScript and implement Worker adapters in TypeScript; factor common DTO/command contracts once rather than independently in Node and Hono. Do not migrate the entire repository or install a new framework. Leave the existing migration-number gap at `019` untouched.
- Domain functions remain pure and synchronous. Application services are asynchronous. Persistence interfaces expose **named atomic operations**, never `transaction(async fn)` or unbounded arbitrary SQL to HTTP handlers.
- Store money and chain quantities as decimal strings. Store internal timestamps as safe integer milliseconds and expose explicit UTC/RFC3339 where appropriate. Distinguish requested cutoff time, observed account time, finalization observation time and ingestion time.
- No network call, object-store call or signature verification inside a database atomic batch. Compute first, then commit only if all read revisions and authority/lease fences still match.
- Preserve all existing immutable decision semantics. An incomplete or stale source holds work; it never becomes a rejected user, a zero-valued observation or a valid empty board. Replays of accepted commands precede new-admission pause checks.
- Keep new migrations additive. Exact numeric prefixes below are illustrative, not reserved: the coordinator assigns `022+` once across all B tasks, retaining the existing `019` gap. Do not backfill that gap, rewrite committed migrations or use the legacy production database.
- Every completed milestone should record its exact command/result and source commit. No aggregate claim that combines tests from different revisions. Commit and push each finished milestone only under the user's existing implementation authorization; do not deploy.

## AE-02 — Atomic D1 repositories and revision boundaries

**Dependencies:** AE-01. **PRD:** 12.3, 13, 15.4; A35 API schema, A37 idempotency, A42 lease fencing, A46 cost controls. **Files:** implement the D1 Earn/operations repositories, shared query/row mappers in `platform/storage/earn-sql.mjs`, `platform/edge/test/earn-repository.test.mjs`, and illustrative `022-earn-revisions.sql`. Add the minimum `platform/artifacts/store.ts` port plus Node and Worker private-object adapters here; AE-07 extends it with public publication orchestration.

**Minimum control ports, required now:** port the existing scope decision, staffing policy/counter, optional-cost reservation/settlement and provider-attempt metering to named atomic repositories before exposing admission or running jobs. Include `readControlSnapshot`, conditional `admitSubmission`, `reserveOptionalCost`, `settleOptionalCost` and `recordProviderAttempt` under the common ports. Match the current calendar-month settlement semantics and pending-commitment headroom. Scope/staffing/cost revisions become commit predicates; don't authorize from an old preflight read. A hosted-admission profile requires configured staffing, while existing explicitly synthetic demos can keep their fixture defaults. Pausing new work preserves accepted replays, claims/read recovery and reconciliation. Configuration changes stay behind the private operator boundary.

**Minimum artifact port, required now:** define private immutable `putIfAbsent(identity, bytes)` and `getVerified(identity)` with exact byte digest/size and explicit `created|exists|unknown` outcomes. Provide Node filesystem and local R2 implementations before AE-04 writes evidence payloads. Restrict private object keys to a private prefix/binding, with no `manifest_catalog` registration or public route. Store verified immutable bytes first, then conditionally commit their D1 reference; an interrupted reference write leaves an unlisted object that can be reconciled. AE-07 handles only the later public privacy-filtered export/catalog saga; it must reuse this port, not introduce a second store. Verify existing objects before accepting an `exists` result.

**Schema:** add `earn_epoch_versions(epoch PRIMARY KEY, revision, admissions_closed_ms, frozen_input_digest)`; add `earn_commit_receipts(operation_id PRIMARY KEY, kind, business_key, request_digest, claim_nonce, state, expected_revision, expected_counts_json, output_digest, committed_ms, UNIQUE(kind,business_key))`; add an explicit ordered audit-head revision if using the existing config-chain writer. Track changes to relevant epoch input tables through a small, documented revision-update layer or SQL triggers, including late approvals, ownership snapshots, price revisions and cutoff facts. The implementation must enumerate every writer that can affect a board, not only submissions. Existing committed rows stay authoritative.

**Atomic pattern:** retrieve a bounded, consistent SQL batch snapshot of inputs and its revision dependencies; calculate outside the database; submit one SQL batch that conditionally claims a unique commit receipt on matching revisions/fence and inserts all dependent records from that claim. Every child write must depend on the current claim. A final SQL guard must abort the batch if expected decision/fact/award counts differ. A no-op revision mismatch returns conflict and recomputes from new input, not partial success. Reusing an existing identical receipt returns the old result; conflicting payload under the same business identity fails.

Admission must combine campaign activity, staff capacity, scope status, closed-board state, evidence reference and idempotency in one conditional write. A read of remaining capacity followed by an unconditional insert is unacceptable. Existing admission-count triggers may be reused, but the limit predicate and final row insert must race safely. Audit-head assignment must use a unique sequence/CAS; concurrent config writes cannot fork the hash chain.

**Acceptance:** actual workerd/D1 test with concurrent requests for the last slot, identical and conflicting idempotency keys, scope/staffing/cost change between preflight and commit, simultaneous optional-cost reservations, a reservation held across month-end, review conflict, board version changed during compute, failure on the last child insert, duplicate allocation and restart/readback. Exactly one valid commit and no partial child rows. Private artifact tests cover identical replay, conflicting bytes, interrupted put/reference and exclusion from public catalog/read routes. Compare committed winner sets and archive commitments against the Node adapter over identical fixture inputs. Test D1 API migrations through the same runner used by local runtime, not a hand-maintained schema copy.

**Failure/retry:** one bounded recomputation may recover a revision conflict; persistent contention returns retryable pending. Never silently retry a final-review payload conflict. **Cost:** fixed-size batches; measure statement/rows/bytes per operation, keep pilot at existing 100 submissions and ten campaigns. **Founder input:** none.

## AE-04 — Evidence source envelope, decoder ports and completeness manifests

**Dependencies:** AE-01; persist through AE-02. **Files:** `platform/evidence/{envelope,sources,ingest,requirements}.mjs`, `platform/evidence/adapters/{recorded,solana-rpc}.mjs`, `platform/evidence/decoders/{damm,farm,ownership,purchases}.mjs`, tests, and proposed `023-evidence-provenance.sql`. Reuse raw account validation already in `quotes/` and pinned protocol layouts where appropriate; do not duplicate valuation math.

**Schema/interface:** `evidence_sources(source_id, kind, chain_genesis, program_config_digest, decoder_version, policy_digest, enabled_revision)`; immutable `evidence_objects(receipt, byte_digest, semantic_digest, source_id, subject, logical_cutoff_ms, observed_slot, observed_ms, ingested_ms, finality, evidence_mode, object_key, size_bytes, status, reason, supersedes)`; `evidence_requirements(epoch, subject, kind, required_cutoff_ms, receipt, status, reason)` with business uniqueness. Store a private payload under a separate object prefix/binding; the public manifest allowlist must never expose these source objects. `evidence_mode` distinguishes synthetic fixture, recorded public capture and runtime read. A boolean `finalized` submitted by an operator cannot alone change that mode.

Adapter returns bounded raw bytes plus source metadata, persisted using AE-02's private immutable artifact port. Decoder verifies exact account owner, layout/discriminator, chain/mint/pool/farm identity and requested subject before producing the current `assessObservation()` input. Preserve current fixed-point arithmetic and policy pins. Identity mismatch is quarantined, never normalized into a passing sample. Reader/provider transport is injected; positive end-to-end acceptance uses a complete synthetic transcript, clearly labeled synthetic. Genuine captured public bytes provide separate decoder/provenance vectors; their existence does not prove complete historical coverage for a wallet/epoch. No real RPC credentials are needed. Implementing a network-capable reader does not authorize invoking it.

`buildCutoffRequirements(epoch)` enumerates accepted submissions, positive reviews needing closing stake evidence, ownership coverage for qualified wallets, all enrolled purchase positions and their contiguous event coverage, action/issuer policy revisions, prior-board and late-approval dependencies. A completion manifest binds the ordered requirement set and receipts to the epoch revision. Legitimate zero-work bootstrap requires campaign/history completeness, not simply zero returned rows.

Separate transaction commitment levels. Confirmed purchase evidence may be provisional; cutoff reconciliation cannot ignore a missing/changed event. Imported direct withdrawals outside the app must consume credit. A missing history interval remains pending. No provider available for exact historical state means the board waits; do not copy the latest account state and assign the requested old timestamp.

**Acceptance:** missing raw account, stale and future observations, wrong source, partial pagination/history gap, changed decoder version, duplicate/corrected receipt, a newer pending sample masking an old verified one, direct withdrawal and finalized board rejection. A complete zero board passes; a broken feed returning no entries does not. Byte-identical replay creates no duplicate persisted evidence/read row, but every actual provider attempt—including retries returning the same bytes or failing before a response—is metered and consumes its configured quota/cost allowance. A deduplicated stored object is not a free provider request. Test legacy fixture labels explicitly and retain fixture provenance after any transform.

**Failure/retry:** retry bounded transport errors; schema/identity failures quarantine; unavailable historical coverage holds. Corrections append `supersedes` and cannot alter verified/finalized history under current policy. **Cost:** existing normalized price payload cap is 24 KiB; retain it. Define raw-account size limits per decoder and reject excess before storage; share market evidence at a cutoff rather than copying it per wallet. No purchased indexer/provider. **Founder input:** none for recorded adapters; actual sources/thresholds are separately reviewed before real eligibility.

Test a bounded batch of 20 jobs or fewer and a configurable execution deadline. **Cost:** derive limits from existing operations usage reservations; count every attempted external call including retries. Start with zero-network local inputs. **Founder input:** none; no live schedule is enabled.

## AE-06 — Complete cutoff snapshots and atomic settlement on D1

**Dependencies:** AE-02/04/05. **Files:** `platform/earn/{snapshot,settlement-service}.mjs`, D1 repository methods, `platform/edge/test/earn-settlement.test.mjs`, proposed `025-earn-input-manifests.sql`.

**Schema:** immutable `earn_input_manifests(epoch, revision, requirements_digest, evidence_digest, policy_digest, previous_board_digest, input_object_key, completed_ms)` and `earn_settlement_attempts(id, epoch, input_digest, status, output_digest, reason, recorded_ms)`. Never accept a bare `sourceComplete:true` from the automated job. Keep the manual fixture CLI available, clearly labeled, but route hosted-ready application settlement through the completeness manifest.

Steps: (1) freeze the admission boundary after the UTC day closes; (2) await final moderation and the declared evidence set; (3) snapshot all required rows and dependency revisions consistently; (4) derive components and rank with existing pure functions; (5) commit board/facts/decisions/streaks using AE-02 conditional batch; (6) schedule each due token/day allocation by actual activation and designated UTC board; (7) commit awards plus burn with budget conservation and unique token/day identity. Record exact input/output digests; preserve original activation vesting even when completion is late.

Correcting source ingestion after a board is final does not rerank or remove an award; it creates an incident/reconciliation record requiring the published decision to be honored.

**Acceptance:** complete scenarios for zero/five/ten/100 winners, one user with multiple token submissions, missing ownership/price/purchase evidence, late positive moderation advancing the approval window only, adjacent-board streak gap, ten overlapping token campaigns, day-one bootstrap, delayed allocation preserving original clock, caps/dust across very large base-unit budgets. Re-run identical scenarios on Node and D1; compare commitment/amount bytes. Race a cutoff evidence update against settlement and prove either one consistent input wins or settlement retries; no mixed state. A failure on last award leaves zero allocation rows.

**Failure/retry:** `pending` names the missing dependency and durable next action; a retry recovers an existing finalized result. Never fall back to an earlier board or convert source outage to empty. **Cost:** maintain the bounded pilot input set; measure maximum statement/parameter/serialized size against the actual pinned local D1 runtime before selecting batch sizing. If necessary stage immutable plan rows, then atomically publish only after complete counts/digests; readers must not see staged rows. **Founder input:** none for fixture/captured-data parity.

**Failure/retry:** content-addressed exact-byte replay is safe; mismatched bytes are held and investigated, never overwritten automatically. Catalog replays are idempotent. Orphan cleanup operates only on unpublished temporary references and cannot delete a published entitlement artifact. **Cost:** no object listing on request paths; bounded get/put/readback counts per new publication, explicit storage growth. **Founder input:** none locally; independent retention destination/credentials are a later release configuration.

## AE-08 — Recovery and reconciliation across both adapters

**Dependencies:** AE-06/07. **Files:** extend `earn/recovery-drill.mjs`; add `platform/recovery/{inventory,export,restore,reconcile}.mjs`, local CLI, `platform/edge/test/recovery.test.mjs`, `platform/recovery/README.md`. No new financial action.

Maintain two distinct restore modes: public read-only archive recovery and full private application recovery. Public recovery imports verified allocations into a fresh read-only namespace/database, with all mutations rejected. Private recovery includes migrations, source/configuration versions, audit head, evidence references, idempotency receipts, pending jobs/leases and published commitment inventory. Sessions should be revoked on private recovery; do not serialize usable session cookies into export files. New process identity invalidates old leases. Record restored source commit/schema fingerprint.

Reconcile board budget = awards + recorded burn, no duplicate token/day, all evidence objects present, every public catalog reference byte-valid, no lost historical bundle, job cursor continuity and expected config head. ## Implementation appendix: exact Cloudflare constraints and algorithms

These details are mandatory for AE-02/03/07, not optional optimization work. They were checked against official documentation on 5 November 2026. Treat limits as a dated planning snapshot and recheck them before a future hosted release.

### D1 limits and session choices

The current [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) specify **100 bound parameters per statement**, **100,000-byte SQL text**, **2,000,000-byte string/BLOB/row**, **30-second query duration**, and **50 MB query result**. Per-statement limits also apply inside a batch. The documented invocation query limits are **50 Free / 1,000 Paid**, but a `batch()` call counts as one query against that invocation limit, not one per statement. This page does not specify a separate aggregate batch-payload byte ceiling; do not invent one or confuse it with the statement limit.

Application proposal: begin with a **256 KiB serialized bound-value batch target**, **100 result rows per page**, existing **100 admitted submissions per epoch**, and a bounded snapshot that references shared market evidence rather than embedding it repeatedly. These are engineering safeguards, not vendor maxima or new product rules. Record actual SQL bytes, parameter count, batch bytes and returned bytes in tests. A 100-wallet `IN (...)` plus other predicates can exceed 100 parameters; use a keyed staging/input relation or bounded chunks. If snapshots span batches, read monotonic dependency revisions before and after, retry on any change, and guard those same revisions at final commit. Bookmarks cannot substitute for those checks.

Use `env.DB.withSession('first-primary')` for current authorization/command preparation, or a previous `getBookmark()` to continue a client's known read position. `first-primary` affects the first query; later reads can use replicas. `first-unconstrained` is appropriate only for deliberately stale-tolerant discovery. Sessions preserve sequential consistency and a supplied bookmark establishes a minimum read position; neither is a fixed snapshot. [Sessions API](https://developers.cloudflare.com/d1/worker-api/d1-database/#withsession)

Proposed HTTP continuation: an optional bounded `X-10X-Read-Bookmark` response header carries an opaque D1 bookmark. The client may return it for its own follow-up read, but the adapter validates its size/format and treats it only as consistency metadata. It grants no authorization, does not select a user/database, and is not an Earn `snapshotId`. Keep financial/business snapshot hashes in their own fields. For current capability/claim reads, retain `no-store` unless the route's explicit public cache policy allows otherwise. Local Miniflare cannot prove geographic replica lag behavior; add a deterministic adapter test for bookmark propagation and list actual remote replication verification as a later release check. [Read replication behavior](https://developers.cloudflare.com/d1/best-practices/read-replication/)

### Guarded D1 commit, step by step

This is the proposed application algorithm, not an undocumented Cloudflare transaction API:

1. Compute a canonical command digest and deterministic business key. Query any committed receipt using the current session. Equal payload returns the stored result; a different digest is a final conflict. This lookup is an optimization; uniqueness still governs the race.
2. Load the bounded immutable evidence inputs and `{epochRevision, policyRevision, sourceRevision, priorBoardDigest}`. Calculate the pure plan outside the DB. Generate a **fresh attempt claim nonce**, separate from stable operation/business identity.
3. Build a single prepared SQL batch. Its first statement conditionally inserts a `state='staging'` receipt only when all expected revisions and the job lease token/expiry still match and no conflicting business receipt exists. All predicates are SQL parameters; no interpolated user identifiers. The entire command's authority/scope checks must also be represented at this atomic boundary where they can change concurrently.
4. Every child `INSERT ... SELECT`/`UPDATE` has `EXISTS` on the receipt's exact `operation_id`, this attempt's `claim_nonce` and `state='staging'`. An old successful receipt must not authorize a new set of child writes. Persist the input/plan digest and expected child counts with the receipt. Do not use `INSERT OR IGNORE` to hide a missing mandatory award or fact.
5. The final statement changes this receipt to `committed`. A `BEFORE UPDATE OF state` trigger with `NEW.state='committed'` checks all required row counts/business links and raises `RAISE(ABORT,...)` on mismatch. Store the final output digest only on this transition. A predicate returning zero rows is **not** an SQL error and does **not** automatically roll back its batch. Therefore a final `UPDATE ... WHERE counts_match` without an abort guard is insufficient: it can leave a partially staged mutation committed.
6. Examine the first/final statement results. If the claim inserted zero rows, no child should have changed. Read the existing receipt: return it only if its command digest matches and its state is committed; otherwise report revision conflict/pending and optionally recompute once. A thrown constraint/guard error means the whole batch failed; query by the stable business key before treating an ambiguous transport failure as retryable.
7. Test the exact SQL under workerd with failure injected into the final trigger, a concurrent changed epoch revision, duplicate command attempts with different claim nonces, expired leases and missing required child records. Verify all-or-nothing rows and unchanged old commitments, not just the API response.

For snapshots needing too many rows in one response, use immutable keyed input pages plus the revision check; for oversized write plans, stage immutable candidate rows that readers never consume, validate their digest/counts, then atomically publish the final pointer/receipt. Staging failure is not partial finalization. It must be safe to abandon or resume an unpublished plan without changing a published board. Keep the simpler single-batch path while it meets the measured pilot bound.

### R2 create-once publication and ambiguous writes

Use bounded bytes, not an unknown-length stream, for the existing small manifest size. `bucket.put(key, bytes, {onlyIf: new Headers({'If-None-Match':'*'}), sha256: byteDigest})` expresses the create-once attempt; typecheck it against the pinned binding declarations and test in local workerd. Worker `put()` returns `null` when its condition fails. This is not an application-success receipt: fetch the existing object and compare its exact bytes/hash before declaring an identical replay. R2 `get()` with a failed condition can return metadata without a body, which also must not be mistaken for valid manifest bytes. [R2 Worker methods and options](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)

Conditional writes are evaluated atomically. A missing object after an unknown write does not prove the earlier write will never commit; do not issue an unconditional overwrite. Retry the same immutable bytes with the create-once condition and reconcile. A read through an external cached domain has different visibility from a direct binding, so publication verification must use the binding, not a CDN URL. [R2 consistency](https://developers.cloudflare.com/r2/reference/consistency/)

Persist `semanticDigest`, `byteDigest` and `publicationOperationId` before uploading. On timeout, retain the same bytes/key/digests; reconcile with bounded conditional retry. On any byte conflict, leave the catalog unchanged and mark held. A successful upload followed by failed D1 publication leaves a recoverable unlisted object, not a public artifact. A successful catalog commit followed by lost HTTP response is recovered from the publication receipt. No delete operation is needed for success or retry. Public claim artifacts are never optional-cache entries and are excluded from routine age-based cleanup.
