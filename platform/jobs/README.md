# Local durable jobs

Migration025 adds immutable job identities, attempts, wake observations, checkpoints and a durable source outbox. The repository shares the same SQL protocol across Node and D1. Acquisition atomically records the attempt and updates the execution fence. Every checkpoint and finish checks token, revision, payload digest, current operator grant and database execution time. Accepted results are immutable; lost responses reconcile stable rows. A source repository can append the named outbox effect under its existing fresh-attempt gate, in the source transaction. Reconciliation recovers the same job before marking the obligation dispatched.

The registry covers capture, cutoff, finalization, allocation, publication, reconciliation and retention. Unattached handlers produce named holds. B05/B07/B08 attach real services; no missing handler fabricates completion. The settlement adapter binds the exact immutable command payload to its job business key and fence. A committed business receipt followed by a crash is replayed, not executed twice.

Node ticks process at most20 jobs. The Worker binding entrypoint currently admits one job per invocation to leave room within the free-profile query budget for cutoff reads; B07 must measure the complete handler before increasing it. A tick deadline is at most5000ms and bounds outbox, acquisition, checkpoints, handlers and completion I/O. A timed-out write has an unknown outcome: the durable lease/outbox survives for reconciliation and no rollback is assumed. Abort prevents new context checkpoints from a late handler. Database execution-time fences still reject stale leases. There is no fetch endpoint, cron, Queue or Workflow registration.

Holds wake only on a new dependency evidence digest or an explicit ready time. Repeated wake digests cannot spin the same job. Retry delays use bounded deterministic-injectable jitter. Only explicitly known read-only transport failures retry automatically. Exhausted/unknown work is held for reconciliation. Completed/failed identities cannot be rewritten.

Provider execution is injected and read-only; no network transport or credentials are installed. It requires explicit free-cost evidence, reserves zero-cost optional work, meters quota before dispatch, checkpoints dispatch and outcome, and preserves failed-call usage. A quota replay alone cannot redispatch. Unknown dispatch remains held even after lease replacement. Completed reads replay only under the exact provider configuration digest. Each job carries one provider step; a new step requires a distinct job identity. Future paid/provider integration remains outside this run.

Run `node platform/jobs/cli.mjs --fixture-rehearsal` for a disposable, zero-network rehearsal with one completed synthetic no-op and one explicit missing-handler hold. `node --test platform/jobs/*.test.mjs` and `node --test platform/edge/test/jobs.test.mjs` cover races, replacement, restart, source rollback, metering, payload binding, lost responses and deadlines. Local job SQL measurements in the race fixture: at most2 statements/batch,21 parameters/statement,634 SQL bytes/statement and1177 encoded batch bytes. The source outbox fixture uses787 encoded bytes. These are fixture measurements, not production pricing/throughput claims.
