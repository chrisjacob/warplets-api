# Local transaction rehearsal

Ported the canonical encoder and bounded legacy/v0 message decoder from the reviewed October branch. The lab verifies the message digest, packet lifetime, local genesis identity, signers, exact programs, ordered instructions, account privileges, lookup evidence and simulated fee/output limits against an independently supplied local plan. Owner signatures must verify against those same message bytes.

Use `node --test transactions/intents.test.mjs` from the platform directory to replay a signed, synthetic receipt through submission, an unknown outcome, confirmation and finalization. Idempotency keys and business identity share one immutable plan. Attempts have their own identities. An ambiguous submission permits reconciliation only. Only an unsubmitted expired packet can be replaced; a new attempt must pass the complete check again.

The operator CLI accepts local evidence files. It has no broadcast method or RPC URL. Submitted/confirmed/finalized are labels on observed fixture events. Only the owner can retrieve an intent summary from the public API. Network provenance, typed production instruction factories, trusted RPC/simulation sources, persistence parity and independent review remain prerequisites to enabling a real adapter.

The portable owner-only recovery repository independently verifies retained plan/packet hashes, attempt order and receipt state paths before returning bounded guidance. It reads at most 16 attempts and 64 receipts, then fences source/recovery changes after hashing. Inconsistent, oversized or changed history stays pending. Unknown/submitted outcomes permit reconciliation only; replacement guidance requires an expired, never-submitted and unfulfilled intent. Legacy records remain labelled unverified local rehearsal; this reader neither signs nor prepares new attempts. Node and local D1 parity evidence: `../validation/runs/2026-11-06-overnight/B15-01.json`.

Economic preparation uses a strict owner-bound request vocabulary and actual retained quote evidence. The economic intent key is separate from request idempotency and preparation identity: repeat requests recover the original immutable preparation, while a new request needs current evidence. Plans retain original supply/activation, quote/source/manifest/program bindings and explicit missing wire, funding and simulation evidence. They create no executable transaction attempt. Historical recovery reconstructs original evidence at its recorded quote time, independently of current market presentation or expired quotes.

The private recorded-outcome service accepts only an intent ID, attempt ID, retained evidence receipt digest, expected intent revision and scoped request key. An operator with existing evidence-ingest authority can import a synthetic recorded outcome for an already unresolved attempt; the service derives all message, signature and state facts from verified private evidence and the retained ledger. It never signs, broadcasts, creates an attempt or upgrades legacy signature authority. Exact legacy observation bytes/event IDs remain unchanged. Existing unbound events return an explicitly unverified legacy replay without a new receipt or provenance backfill.

New provenance-bound state transitions are atomic with their sidecar and command receipt. Raw legacy writes cannot rewrite protected attempt identities or bypass recorded transition guards. The public recovery view remains owner-only, private/no-store and nonexecuting on Node and Worker; missing or inconsistent history returns a pending error rather than optimistic guidance.
