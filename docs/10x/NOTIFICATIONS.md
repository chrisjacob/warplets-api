# Isolated notification infrastructure

Migration 0020 introduces app-scoped subscriptions, encrypted tokens, settings, signed-event deduplication, an immutable event log and a durable leased outbox. Preferences default to opt-out. Live registration and delivery remain disabled; there is no HTTP sending transport or configured webhook verifier. The local UI can save topic preferences but cannot request real notification permissions.

The tested adapter uses the same pinned `@farcaster/miniapp-node` verifier as the existing apps, with real Ed25519 JFS signatures. Its injected key verifier must establish the signing key/FID/requester relationship; the authorized client FIDs and exact HTTPS receiver URLs are allowlisted. The launchpad has its own fixed scope and canonical origin, and does not import another app's tokens, associations, credentials or IDs. The protocol does not supply a general signed event sequence number; permanent signature deduplication and explicit in-app opt-in protect against replayed enables overriding opt-out. A disable/removal requires opt-in again. Stale previously unseen host events remain a reconciliation concern for future live registration.

Tokens are AES-256-GCM encrypted with AAD binding scope, canonical origin, user and client. Production needs an owner-controlled secret key, rotation/retention procedures and approved verification allowance. The ephemeral tests do not establish production key custody. Neither tokens nor raw signed bodies are returned by public diagnostics.

Events derive from a ready open round, a confirmed launch receipt, or a positive finalized allocation with a funding receipt after the approved release-plus-one-second vesting boundary. An unfunded/future allocation cannot generate a rewards notice. Daily UTC cap: three distinct events per user across clients. Stable IDs deduplicate deliveries. Topic opt-outs, independent pause, exact receiver checks, expiry, bounded batches, five-attempt retry ceiling and exponential rate-limit backoff are enforced. Tokens and settings are rechecked immediately before fake transport. Invalid tokens are revoked without overwriting a newer subscription.

Lost responses and expired processing leases become unknown; a receipt reconciler may mark them sent. They are never blindly retried. All executed tests use fake transport and disposable keys, including concurrent drains, caps, rate limits, signature tampering and accepted-but-lost responses. No real notification is sent and normal scheduled operations do not activate this adapter.

Before live use: canonical-domain registration, association, verified client configuration, encrypted secret custody, bounded verification budget, receiver rate-limit pacing, real host permissions, signed webhook transport wiring and separately authorized delivery. `addMiniApp` needs the production domain; a temporary QA tunnel cannot certify it. See [Farcaster notifications](https://miniapps.farcaster.xyz/docs/guides/notifications).
