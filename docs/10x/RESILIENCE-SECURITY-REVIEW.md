Reviewed 31 October 2026, following the Warplet component and guided-experience work in PR #125. This review preserves the mobile-first layout and existing Connect flow.

The final tidy-up and owner/development release checklist are in [REVIEW-TONIGHT.md](REVIEW-TONIGHT.md). PR #126 remains the current review entry; no new review branch or merge is needed for this handoff.

## Findings and changes

| Area                 | Finding                                                                                                                                                            | Change                                                                                                                                                                                                                                                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Account changes      | A second tab could replace the session cookie while the first tab still displayed the previous participant.                                                        | Votes, Solana verification requests and notification preferences send the displayed FID as an optional precondition. The Worker compares it with the authenticated session before changing a vote, wallet challenge or preference. Mismatches return 409 with reconnect guidance.                                                                            |
| Private preferences  | Settings loaded while their disclosure was closed; a response needed account and shape checks before use.                                                          | Load the settings code and data only after opening Notifications. Validate the response identity and binary settings; disable fields during loading/account errors, offer retry or reconnect, cancel requests on unmount, and restore the previous selection on an ordinary save failure. Closing and reopening does not refetch an already mounted section. |
| Market context       | Reloading a chart reset its period. New market cards also omitted the chosen period from their destination.                                                        | Persist `market` and `marketWindow` independently of the trading leaderboard's `window`. New share cards include the period. Existing immutable cards remain unchanged.                                                                                                                                                                                      |
| Trading context      | A profile opened from a board could lose its window and snapshot on reload; returning could lose the trading view.                                                 | Persist trading mode and period, pin an opened profile to the displayed board ID, and clear the profile pin on an explicit return or leaderboard switch.                                                                                                                                                                                                     |
| Chart readability    | Intraday endpoint labels could show the same date; padded price axes could suggest a value below zero.                                                             | Show times for a chart spanning at most 24 hours, retain full endpoint date/time titles, and clamp the indexed price axis at zero. Missing evidence and price gaps remain explicit.                                                                                                                                                                          |
| Guidance and results | Finishing first-visit onboarding removed its opener, leaving focus without a useful destination. Profile ROI formatting differed from the other performance views. | Restore focus to the next available participation action or selected tab when the opener has disappeared. Reuse signed percentage and positive/negative styling for trader metrics.                                                                                                                                                                          |

The FID header is **not authentication**. A valid origin-bound cookie session is still required. A header alone cannot establish identity, and legacy callers without the header retain cookie-based authentication. The header narrows the intent of these updated callers; it does not replace the session, origin, challenge, signature or authorization checks. Existing Base/Farcaster shared sign-in code is unchanged.

## Validation

Optional modules now have small, independent error boundaries. An unavailable market, leaderboard, rewards/history view, notification settings chunk or guide displays a contained reload action instead of unmounting the app. The guide can be dismissed with focus returned to a usable control. Header/navigation and today's round survive; private rewards and preferences do not share a failure boundary. Reload preserves URL context and never retries a participant or financial action automatically. Browser tests deliberately abort each module and exercise recovery; raw exceptions stay out of the UI.

- App and Worker typechecks, import boundaries, 127 core tests and 11 script checks pass. Production frontend build and Worker deployment dry run pass.
- All 92 browser regressions pass across desktop and mobile Chromium plus targeted mobile WebKit. Added cases exercise collapsed preferences, malformed-response recovery, stale-account preference/vote rejection, market period reloads, pinned profile/back navigation and failed optional modules. Existing onboarding focus coverage now checks the next participation action.
- All 10 populated QA/admin journeys pass against the separate synthetic database. The QA transport preserves the account precondition; it supplies no new production authentication path.
- The request-count regression observes **zero preference reads and zero settings chunks before opening Notifications**, then no extra preference read on a simple close/reopen. The production manifest gate also rejects eager settings imports.
- Static startup is **76.1 KiB gzip**, below the unchanged 80 KiB limit. QA seed data and simulation UI remain excluded from production JavaScript.
- Root security preflight, redirect, Solana dependency and rendering regressions pass. The production audit reports no unignored moderate/high/critical findings. Its two existing ignored high browser-installer findings and low Deepmerge CSS-tooling finding remain; see [the security baseline](SECURITY-2026-10-31.md). No new dependency or audit exception was introduced.
- Local screenshots cover Today, Rewards, Leaders, History, expanded preferences and the matched-price chart at phone widths, plus 320px and desktop layouts. The owned browser harness reports no page exceptions or horizontal overflow. Refreshing the local QA server preserved the active seed manifest and database.

Reviewed the current Worker handler contract against `@cloudflare/workers-types@5.20261031.1`; no new platform API, binding, migration or configuration is needed. The package's existing pinned types remain unchanged.
