# Participation rules for review

Status: **current participation design approved by the owner on 30 October 2026** for the future controlled cohort. The owner's response was “Proceed with the current design.” [The approval record](approvals/2026-10-30-design.json) binds that decision to the exact reviewed Git commit, blob and SHA-256. The policy is recorded as `participation-v1-2026-10-30`; runtime `local-v1` and historical settlement manifests remain unchanged. Deployment, signing custody, token launches, funding, claims and new provider spend remain separately gated.

The accepted controlled-cohort design retains these development policies and their stated limits:

| Area               | Approved design and limits                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Timetable          | UTC: open previous day 20:00, close 19:30, target launch 20:00. Freeze ownership and links before reveal/open. Never freeze late and pretend it was on time.                                                                                                                                                                                                               |
| Identity           | Farcaster FID with verified Solana reward wallet. Base links are optional boosts, verified by EOA or smart-wallet signatures. NFT attribution uses authoritative ownership and frozen Base links.                                                                                                                                                                          |
| Duplicate controls | A wallet is reserved to one FID per round. Ambiguous Base ownership links receive no NFT attribution. This establishes wallet/account uniqueness only; it does not establish one human per FID. Further Sybil, dispute and disqualification policy remains required before public participation.                                                                           |
| Voting             | One changeable vote per FID; earliest valid vote time and first-vote reward/holding wallet scope remain frozen through changes. Votes are advisory. The operator selects one candidate or skips.                                                                                                                                                                           |
| Attributes         | Commit a random ten-attribute cycle before opening. Reveal one attribute per day; reveal seed/order proof at the end. Highest eligible NFT level applies; owned NFTs do not stack levels.                                                                                                                                                                                  |
| Boost              | Base 1× + 0.3× per attribute level (up to +3×) + holding up to +5× + streak up to +1×. Add once and cap at 10×. Base valid vote is 10 points.                                                                                                                                                                                                                              |
| Streak             | +0.1× per consecutive valid offered round, maximum ten. Missing an offered round resets it; unavailable/unoffered rounds do not.                                                                                                                                                                                                                                           |
| Holding            | Retained purchase value in USD; acquired lots use their acquisition clock. Credit below $10 is zero, $10–<$100 earns one point/day, $100+ earns two/day. Integrate elapsed retained-lot value across active campaigns, normalize by twice active-campaign opportunity time, floor once and cap at +5×.                                                                     |
| Disposals          | Proportional credit reduction across purchased and airdropped inventory. Verified internal transfers preserve cost/clocks; external incoming transfers have no acquisition credit; rebuys start a new clock. No current market-value credit.                                                                                                                               |
| Evidence           | Complete finalized token-account history from launch; exact receipt reconciliation; independently sourced historical payment-asset USD price. Unsupported swaps, unknown prices, stale observations or incomplete history block finalization. Pyth HTTPS evidence currently uses endpoint trust, not VAA verification; accepting this trust model is an explicit decision. |
| Ranking            | Positive valid votes, descending exact boosted points; earliest valid vote then FID breaks ties. Top 100 share the full daily allocation, including when fewer than 100 qualify.                                                                                                                                                                                           |
| Precision          | Integer/rational arithmetic. Largest remainders distribute indivisible token units; equal remainders follow rank. No floating point token allocation.                                                                                                                                                                                                                      |
| Release            | 90% liquidity and 10% rewards, ten allocations of 1% of supply at actual launch +24h through +240h. Closing rounds serve releases in `(close, close +24h]`, independently of whether a new launch was skipped.                                                                                                                                                             |
| Reserve            | Zero qualifiers reserve the full release. An unoffered round needs an explicit audited reason. Reserves cannot silently be redistributed; treasury destination and ultimate use remain undecided.                                                                                                                                                                          |
| Finality           | Scores provisional until immutable settlement. Finalized, funded, released and claimed are separate facts. This build creates only finalized **unfunded** entitlements. Corrected evidence never recalculates historical finalized allocations.                                                                                                                            |

The owner also chose Jito evaluation with fully locked rewards. Specific vesting/clawback parameters and custody addresses were not supplied by that choice; the concrete [Jito proposal](JITO-LOCKED-PROPOSAL.md) remains for review. The approved participation design accepts the documented source trust and wallet-level duplicate controls for continued implementation. It does not define unspecified public Sybil/dispute procedures or a destination for reserved funds. Those operating details, real-wallet QA and separate release authorization remain production gates. An activated rules version will apply only to future rounds.
