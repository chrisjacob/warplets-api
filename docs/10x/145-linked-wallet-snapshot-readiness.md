## Publication order and original guards

The successful snapshot publisher accepts an optional distinct `cohortId`, supplied by the existing caller's `cohortPublicationId`. It preserves the original receipt position, original evidence decoding and analysis comparison, ordered run/candidate/attempt/completion/work/profile statements, original result vector and source accounting. Receipt-free control, catch-up and failed batches cannot opt into a cohort link. The cohort identity cannot equal the producer, receipt stage, lease publication or original job identity; caller-level uniqueness still covers the other retained workflow/source identities before acquisition.

Candidate and snapshot publishers now share `retainLinkedCohortReadiness` and domain-scoped recovery. The snapshot plan retains an optional `cohort_id`. A fenced preview authenticates the original staged wallet receipt, verifies the original accepted lease parent and applies the original **current** snapshot dispatch checks. It executes only the original candidate wallet-analysis update inside a rolled-back transaction, then captures the unchanged original `captureCohort` statements for that projected candidate. No receipt, profile, run or lease-completion row is published by the preview; the original merge/triggers are retained and all preview effects roll back.

The existing parent `candidate_hash` pins the complete candidate **before** the snapshot update, while the child's `candidate_hash` pins the projected candidate **after** it. The parent's nullable `source_hash` still binds the original wallet evidence. These hashes serve different purposes and are never substituted for one another. The original cohort builder still chooses the maximum evidence timestamp and retains all policy, eligibility, first-observation and assessment-hash rules.

Encrypted child readiness precedes parent readiness and producer SQL. The authenticated child embeds the exact original parent and first-row fingerprints. Journal publication and native snapshot publication require the matching companion plan. Inside the real producer transaction, first-row checks precede producer SQL, the unchanged snapshot checks require its accepted original lease plus the current candidate/source/pause/backoff state, and the final projected-candidate hash check precedes commit. Late receipt/candidate/profile/completion failure rolls back the original producer batch atomically. Earlier collected cache data, staged bytes, charged allowances and independent bookkeeping remain; no spend is refunded or source call repeated.

Existing callers without a cohort ID and all saved unlinked plan formats retain their previous behavior. Existing identities must use their original recovery path; no link is retrofitted under an old identity. The target schema, encrypted journal version, source formats, quotas and scoring model are unchanged. CI's existing snapshot and candidate suites include the new cases without a new package command or dependency.

## Recovery and outcomes

`recoverLinkedWalletSnapshotBatch` accepts only the retained cohort ID and `publish` or `reconcile`, alongside the existing private context and grant. It shares the candidate pair's strict absent-parent materialization, immutable identity, partial/corrupt-file and ownership rules, while admitting only a successful receipt-backed snapshot parent. Candidate-only recovery rejects snapshot parents, and snapshot-only recovery rejects candidate parents before publication or materialization.

Pending snapshot execution still requires the original append grant and a currently accepted original lease, unchanged source/candidate and unpaused/non-backed-off state. A lease at its exact expiry is invalid. Recovery never renews it, resets a job, reselects a token, redispatches a source request or refunds a reservation. An absent parent intent may be materialized from its authenticated original child under the original grant; materialization grants no current lease or execution permission. Partial or conflicting parent/child directories remain held and are never resealed automatically.

Once the parent has committed, its read-only reconciliation checks the original accepted parent/receipt/result history without requiring a new active lease or today's candidate. The original captured cohort may then finish under its original grant even after lease expiry or later candidate changes. This records the original committed assessment; it does not refresh evidence or create action authority. A replacement owner may reconcile both already committed publications but cannot execute former-owner pending work.

Inspect `state`, `producer`, `cohort` and `failure`, plus the recorded cycle's original `result`, publications and producer/cohort/post_commit outcomes. Lost producer acknowledgement can leave a committed snapshot with an unconfirmed cohort. Failed read-only recovery preserves any confirmed parent result and reports `reconcile`/`read_only`; it never falls back to publishing. The original wallet caller's later failure bookkeeping remains separate from the committed successful snapshot row, as before.
